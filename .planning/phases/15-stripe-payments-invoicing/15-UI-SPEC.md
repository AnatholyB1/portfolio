# Phase 15 — UI Design Contract

> Visual and interaction contract for phase 15. Generated by gsd-ui-researcher (auto chain, non-interactive).
> Baseline: `13-UI-SPEC.md` and `14-UI-SPEC.md` (same design system, tokens, `pt-*` classes, copy tone). No new tokens, no new fonts, no new colors.
> Surfaces: (A) portal "Paiements" tab and return pages, (B) admin project sheet "Facturation" section (period-invoice form, credit-note form, invoice list, unreconciled payments view), (C) invoice and credit-note PDF deltas, (D) emails.
> Sources: 15-CONTEXT.md (D-01..D-18), 15-RESEARCH.md (return URLs `/espace-client/paiements?facture={id}&retour=succes|annule`), 13-UI-SPEC.md, 14-UI-SPEC.md.
> Authenticated zone: prices are allowed in portal and admin. French only, `noindex`, sober back-office.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (inherited: custom `pt-*` CSS, no `components.json`; shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none (native elements + `pt-*` classes) |
| Icon library | `lucide-react`, 16px, `aria-hidden="true"`. New icons: `CreditCard` (pay), `Clock` (paiement en cours), `Receipt` (invoice), `Undo2` (avoir), `AlertTriangle` (unreconciled) ; reused `Check`, `Download`, `Lock` |
| Font (portal/admin) | Body Manrope, headings Space Grotesk, mono JetBrains Mono (invoice numbers, hashes, Stripe references) |
| Font (PDF) | Manrope 400 + 700 embedded (phase 13 `fontData.ts`) |

Scoping: portal styles in `src/components/portal/project/project.css` under `.pt-root`; admin in `src/components/admin/projects/projects.css` under `.pt-admin`. New class prefix `pt-pay-*` (portal payments) and `pt-bill-*` (admin billing). No cinema, no custom cursor, no GSAP, no decorative animation; color/border transitions 150-200ms only.

## Spacing Scale

Same scale as phases 13-14 (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon gap, label-to-value gap |
| sm | 8px | Badge padding, gap between row actions, label-to-input gap |
| md | 16px | Card padding, form field gap, table cell padding |
| lg | 24px | Gap between panels, card padding on desktop |
| xl | 32px | Gap between invoice list and unreconciled view |
| 2xl | 48px | Page top padding below nav |
| 3xl | 64px | Not used |

Exceptions: interactive targets min 44px (Pay button 48px high on mobile, full width <640px). Left rule on "paiement en cours" and "non rapproché" rows is 2px (existing `.pt-warning` precedent). Period-line grid columns: désignation 1fr, jours 96px, TJM 144px, montant 144px, remove 44px.

## Typography

3 sizes (14, 16, 24), 2 weights (400, 500), identical to phases 13-14.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (cell text, form values, paragraphs, motif text) | 16px | 400 | 1.5 |
| Label / meta (column headers, labels, badges, dates, hashes, helper) | 14px | 500 (labels, badges), 400 (meta) | 1.5 |
| Heading (page title "Paiements", section titles, return page title) | 24px | 500 (Space Grotesk, letter-spacing -0.02em) | 1.2 |
| Display | not used | n/a | n/a |

Monospace (JetBrains Mono, family variation only, 14px/400): invoice number `FA-2026-0001`, `AV-2026-0001`, test series `TFA-` / `TAV-`, SHA-256, Stripe references. Amounts: `font-variant-numeric: tabular-nums`, right-aligned, `formatEuros(cents)` (`1 234,50 €`, U+00A0, never `Intl` fr-FR). Credit-note amounts display as positive with the "Avoir" label (no minus sign). Dates `formatDateFr`.

## Color

Existing dark tokens only (`globals.css`), unchanged.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` #0A0B0C | Page background |
| Secondary (30%) | `--bg-2` #111213 (cards, tables), `--bg-3` #16181a (badges, summary blocks, preview frame, read-only panels) | Surfaces |
| Accent (10%) | `--acid` #C4F542 | see reserved list |
| Destructive / error | `--warm` #E07856 | Errors only (`.pt-error`). The credit note is a legal correction, not a deletion; its submit is a primary-neutral confirm, not destructive-styled |
| Text | `--ink`, `--ink-dim`, `--ink-faint` | |
| Borders | `--line`, `--pt-border-strong` | |

Accent reserved for (exhaustive):
1. Portal: the single primary button "Payer l'acompte" / "Payer la facture" / "Payer le solde" of the first unpaid invoice. Other unpaid invoices use `.pt-btn-ghost`, so only one accent button is visible per page.
2. Admin: the single primary button of the open form: "Émettre la facture" (period invoice, after preview) or "Émettre l'avoir" (credit note, after confirm step).
3. `:focus-visible` outline (2px `--acid`, offset 2px) and checked state of the refund checkbox (`accent-color: var(--acid)`).

Not accent: "Télécharger", "Aperçu", "Ajouter une ligne", "Copier", "Retour aux paiements", "Rapprocher" (ghost/text). Status badges are neutral (`--bg-3`, 1px `--pt-border-strong`), never green/red: meaning is carried by text plus icon.

Status badge contract (24px min-height, 0 8px padding, 14px/500, 8px radius):

| Status | Label | Icon | Derivation |
|--------|-------|------|------------|
| `to_pay` | À payer | none | issued, no confirmed payment, no pending session |
| `processing` | Paiement en cours | `Clock` | Checkout done or bank transfer awaiting, webhook final not received (D-04) |
| `paid` | Payée | `Check` | verified webhook only (PAY-02) |
| `credited` | Avoir | `Undo2` | credit note total covers invoice; partial credit shows "Payée" plus meta "Avoir partiel de {x} €" |
| `refunded` | Remboursée | `Undo2` | optional Stripe refund confirmed by webhook |

## Surface A — Portal "Paiements" tab (`/espace-client/paiements`)

Server component, RLS client. `ClientNav` third link enabled: `Projet`, `Documents`, `Paiements` (replaces disabled "Paiements (bientôt)"; `aria-current="page"`). Update `portalPage.test.ts` nav assertion deliberately. Prices allowed.

### A1. Layout

1. `h1.pt-heading` "Paiements".
2. With several projects: `ProjectSelector` and per-project `h2` (same rule as Documents).
3. **Next payment card** (only when at least one invoice is `to_pay`): `.pt-card` `--bg-2`, `h2` "À régler" (24px), then for the first unpaid invoice: type label ("Acompte", "Facture de période", "Solde"), number (mono), échéance, amount (24px/500 tabular-nums, the only large number on the page), and the primary `.pt-btn-primary` with `CreditCard`: "Payer l'acompte" / "Payer la facture" / "Payer le solde". Under the button (14px `--ink-dim`): "Paiement sécurisé par Stripe : carte bancaire ou virement." When the invoice is the acompte: helper "Le paiement de l'acompte lance la production de votre projet."
4. **Invoice table** `.pt-table`, `<caption class="pt-sr-only">Factures du projet {title}</caption>`:

| Column | Content |
|--------|---------|
| Facture | `Receipt` 16px + type label + number (mono 14px) ; for avoirs "Avoir {number}" with meta "Avoir sur la facture {number}" |
| Émise le | `formatDateFr` |
| Période | "du {date} au {date}" for period invoices, else empty "—" |
| Montant | `formatEuros`, right, tabular-nums (HT = TTC, caption note below) |
| Statut | status badge |
| Action | `À payer`: `.pt-btn-ghost` "Payer" (primary only for the first unpaid, see accent rule) ; `Paiement en cours`: no pay button, meta "Nous attendons la confirmation de Stripe." ; `Payée`: meta "Payée le {date}" ; always `.pt-btn-text` "Télécharger" (`Download`, label "Préparation…" while the signed link is generated, same flow as Documents) |

Order: unpaid first, then by émission date descending. Avoirs listed right under their invoice, en retrait (`.pt-doc-replaced` look reused: `--ink-dim`, 2px left `--line-strong`, 16px indent).
Below the table (14px `--ink-dim`): "TVA non applicable, art. 293 B du CGI : les montants affichés sont TTC."

Mobile (<640px): stacked-card mode with `data-label`; Pay button full width 48px; sticky bar not used.

### A2. Pay interaction

- Click "Payer…": button `disabled`, label "Redirection vers Stripe…", server action creates the Checkout session (amount never sent by the client, D-05) then `window.location.assign(session.url)`. Double-click safe.
- Failure: `.pt-error` in `aria-live="polite"` under the card: "Le paiement n'a pas pu démarrer. Aucun montant n'a été débité. Réessayez dans un instant ; si le problème continue, écrivez-nous."
- Invoice already paid or in progress when clicking (stale page): "Cette facture est déjà réglée ou en cours de règlement." plus page refresh.

### A3. Return pages (same route, query-driven, never marks paid)

`?facture={uuid}&retour=succes` (uuid validated, otherwise falls back to the plain list). Banner `.pt-card` at the top above the list, `h2` receives focus (`tabIndex=-1`):

| State | Copy |
|-------|------|
| `retour=succes`, invoice still not confirmed | `Clock` + "Paiement reçu, confirmation en cours" / body "Stripe nous confirme votre paiement. Cela prend généralement quelques secondes. Cette page se met à jour automatiquement." (`router.refresh()` polling every 3 s for max 30 s, then stops and shows "La confirmation prend plus de temps que prévu. Vous recevrez un e-mail dès qu'elle arrive.") |
| `retour=succes`, webhook confirmed (paid) | `Check` + "Paiement confirmé" / body "Merci. La facture {numéro} est réglée. Un reçu vous a été envoyé par e-mail." + for acompte: "Votre projet passe à l'étape suivante : la production." |
| `retour=succes`, bank transfer (processing) | `Clock` + "Virement en attente" / body "Effectuez le virement avec les coordonnées affichées par Stripe. Votre facture passera en « Payée » dès que Stripe aura reçu les fonds (1 à 3 jours)." |
| `retour=annule` | "Paiement annulé" / body "Aucun montant n'a été débité. Vous pouvez reprendre le paiement quand vous le souhaitez." with `.pt-btn-ghost` "Reprendre le paiement" |
| Payment failed (async failure webhook) | `.pt-error` "Le paiement n'a pas abouti. Aucun montant n'a été débité. Vous pouvez réessayer." plus pay button reappears |

Banner has `.pt-btn-text` "Fermer" removing the query string. No accent button in the banner.

### A4. Other states

- Empty: `h2` "Aucune facture pour le moment" / `.pt-helper` "Votre facture d'acompte apparaîtra ici dès la signature du contrat. Vous recevrez un e-mail à chaque nouvelle facture."
- Load error (server): `.pt-error` "Vos factures n'ont pas pu être chargées. Actualisez la page ; si le problème continue, écrivez-nous."
- Download error: reuse "Le téléchargement n'a pas pu démarrer. Réessayez dans un instant ; si le problème continue, écrivez-nous."
- Test client (flag `test`): a `.pt-warning` line above the table "Mode test : aucun paiement réel ne sera effectué." Numbers are `TFA-` prefixed.

## Surface B — Admin project sheet, section "Facturation" (`/admin/projets/[id]`)

New `.pt-card` section after "Documents", `h2.pt-heading` "Facturation". Client components only for forms; reads server-rendered. Prices allowed. Test-flag projects display `.pt-warning` "Projet de test : séries TFA- / TAV-, clés Stripe de test."

### B1. Summary strip

`.pt-bill-summary` (`--bg-3`, 1px `--line`, 8px radius, 16px padding, `dl` in a 2-4 column grid): Total du devis, Acompte ({p} %), Facturé (sum issued), Encaissé (sum paid), Reste à facturer. Values 16px tabular-nums, keys 14px `--ink-dim`. A Stripe-paid acompte shows meta "Acompte payé via Stripe le {date}" (signals that Stripe payment exists before manual fact gestures, D-10), and where manual `deposit_received` / `balance_received` gestures exist, the `.pt-warning` line (14px): "Un paiement Stripe existe pour ce fait. Toute correction manuelle est journalisée."

### B2. Automatic invoices (informational)

Two read-only lines, no form: "Facture d'acompte : émise automatiquement à la signature du contrat" with state (En attente du contrat / Émise {number}), and "Facture finale : émise automatiquement après le PV de recette signé, déduction de l'acompte" with state. Helper under the final line (14px): "La facture finale ne facture que le travail non déjà facturé en périodes."

### B3. Period invoice form (D-08)

Entry: `.pt-btn-ghost` "Nouvelle facture de période" opens the form inline (no modal). One form open at a time (period or credit note).

Fields (`.pt-label` above, inputs min 44px, errors `.pt-error` with `aria-describedby`/`aria-invalid`):
- Période couverte: two `date` inputs "Du" and "Au" (required, Au >= Du), helper "Mois civil ou sprint de deux semaines."
- Repeating line group (`fieldset` per line, `legend.pt-sr-only` "Ligne {n}"): Désignation (text, max 200), Jours (decimal, comma, step 0,5, min 0,5), TJM HT (€, comma, converted to cents), Montant HT (read-only computed, tabular-nums). "Ajouter une ligne" `.pt-btn-ghost` (max 30, then disabled with helper "30 lignes maximum"); remove `aria-label="Supprimer la ligne {n}"` (unsaved form only, no confirmation). At least one line.
- Références (all facultatif): Numéro de commande, Date d'échéance (default émission + délai de paiement from `SELLER_V1`).
- Totals `.pt-doc-totals` right-aligned: "Total HT {x} €", "TVA non applicable, art. 293 B du CGI", "Total TTC {x} €". Server recomputes; the preview is authoritative.

Actions row (`display:flex; gap:8px; flex-wrap:wrap`): `.pt-btn-ghost` "Aperçu", `.pt-btn-primary` "Émettre la facture" (disabled until a preview of the current values exists; editing any field invalidates the preview). Preview region reuses `.pt-doc-preview` (iframe 720px / 480px <640px, banner `.pt-warning` "Aperçu non conservé. Ce fichier n'est pas celui qui sera émis. Le numéro sera attribué à l'émission."; invoice preview shows "PROFORMA" stamp until emitted).

Confirm panel (inline, `role="group"`, focus on title, Escape cancels): title "Émettre la facture ?" body "Un numéro définitif sera attribué, la facture sera figée et visible par le client, et un e-mail lui sera envoyé. Une facture émise ne peut être corrigée que par un avoir." Buttons: `.pt-btn-primary` "Confirmer l'émission" (in flight "Émission en cours…", disabled; `invoiceId` generated client-side per form open for idempotency), `.pt-btn-text` "Annuler".

Result states (`aria-live="polite"`):
- Success `.pt-success`: "Facture {numéro} émise. Le client a été notifié par e-mail." (form closes, list refreshes)
- Already issued: `.pt-success` "Cette facture est déjà émise."
- Mail failed but issued: `.pt-warning` "Facture émise. L'e-mail n'a pas pu partir immédiatement, il sera renvoyé automatiquement."
- Partial failure resumed: `.pt-warning` "Facture {numéro} émise, mais le lien de paiement n'a pas pu être préparé. Il sera recréé à la prochaine ouverture par le client."
- Validation: per-field errors plus summary "Corrigez les champs indiqués puis relancez l'aperçu."
- Guard: "Le contrat n'est pas encore signé : émettez les factures de période après l'acompte." (period invoices require `contract_signed`)
- Generic: `.pt-error` "La facture n'a pas pu être émise. Rien n'a été envoyé au client. Réessayez ; si l'erreur persiste, contactez le support technique."

### B4. Invoice list

`.pt-table` "Factures du projet" (caption `pt-sr-only`), newest first, avoirs en retrait under their invoice. Columns: Numéro (mono, `Receipt`), Type (Acompte, Période, Solde, Avoir), Émise le, Montant, Statut (badge), Empreinte (first 12 hex mono + `Voir l'empreinte` disclosure revealing 64 chars with "Copier l'empreinte"), Actions: `.pt-btn-text` "Télécharger", `.pt-btn-text` "Voir les données", and for `paid` / `to_pay` / `processing` invoices not fully credited `.pt-btn-ghost` "Émettre un avoir" (`Undo2`). Mobile: stacked cards.

Disclosure "Voir les données" reuses `.pt-doc-snapshot`: header "Données figées à l'émission", vendeur / acheteur / régime de TVA / lignes / totaux / période / déduction d'acompte as `dl`, "Lecture seule. Pour corriger, émettez un avoir." and `Lock` 16px. Paiement block: Stripe reference (mono, Copier), mode (test / live), confirmation date, source "Webhook vérifié".

Empty: `.pt-helper` "Aucune facture pour ce projet."

### B5. Credit-note form (D-14)

Opened by "Émettre un avoir" on a row; inline below the list, heading `h3` "Avoir sur la facture {numéro}" (16px/500) and context recap line (14px `--ink-dim`): "Montant facturé {x} €, déjà crédité {y} €, crédit maximal {z} €".

Fields:
- Type (radio): "Avoir total" (amount prefilled to the maximum, read-only) / "Avoir partiel" (reveals Montant à créditer, € with comma, required, 0,01 to maximum, error "Le montant doit être compris entre 0,01 € et {z} €.").
- Motif (`textarea`, required, min 3 rows, max 1000 chars, counter "{n} / 1000"), helper "Le motif figure sur l'avoir remis au client."
- Remboursement Stripe: native checkbox in a 44px `label`, "Rembourser aussi le client par Stripe" (unchecked by default, `accent-color: var(--acid)`). Visible only when the invoice is `paid` via Stripe. Helper (14px `--ink-dim`): "Frais Stripe : 0,50 € par remboursement, non restitués. Le remboursement est confirmé par Stripe sous 1 à 3 jours. Sans cette case, l'avoir est émis sans mouvement d'argent." Unchecked and invoice unpaid: helper "La facture n'étant pas payée, l'avoir l'annule sans remboursement." and the checkbox is hidden.
- Actions: `.pt-btn-ghost` "Aperçu de l'avoir", then confirm. Primary `.pt-btn-primary` "Émettre l'avoir" is disabled until the motif is valid and a preview exists. A pending payment session of the credited invoice is expired server-side (stated in confirm body).

Confirm panel (inline, focus on title): title "Émettre l'avoir ?", body "L'avoir est un document légal numéroté : il ne pourra ni être modifié ni supprimé. {Si case cochée : Un remboursement de {x} € sera demandé à Stripe.}{Sinon : Aucun remboursement ne sera effectué.} Le client sera notifié par e-mail." Buttons: `.pt-btn-primary` "Confirmer l'avoir" (in flight "Émission en cours…"), `.pt-btn-text` "Annuler".

Results:
- Success `.pt-success`: "Avoir {numéro} émis sur la facture {numéro}." plus when refund: "Remboursement demandé à Stripe : en attente de confirmation."
- Refund pending in list: avoir row meta "Remboursement en attente de Stripe" with `Clock`; confirmed: "Remboursé le {date}".
- Refund failed (webhook): `.pt-warning` row line "Le remboursement Stripe a échoué. L'avoir reste valable. Traitez le remboursement depuis le tableau de bord Stripe."
- Error: `.pt-error` "L'avoir n'a pas pu être émis. Rien n'a été modifié. Réessayez ; si l'erreur persiste, contactez le support technique."
- Over-credit guard: "Le montant dépasse le crédit possible sur cette facture."

### B6. Unreconciled and pending payments view (D-04)

Sub-section `h3` "Paiements en attente ou à rapprocher" (visible when any row exists, else a `.pt-helper` "Aucun paiement en attente."). `.pt-table`, `AlertTriangle`/`Clock` per row, 2px left `--warm`-free rule (`--pt-border-strong`; `--warm` only on the error text). Columns: Facture (number mono), Reçu le, Montant attendu, Montant reçu, Écart (tabular-nums, signed with words "Trop perçu {x} €" / "Manque {x} €"), Statut ("Virement en attente" / "Écart de montant" / "Paiement sans facture reconnue" / "Échec du paiement"), Référence Stripe (mono, Copier), Action `.pt-btn-text` "Ouvrir dans Stripe" (external link, `ExternalLink` 16px, `rel="noopener noreferrer"`). Read-only: the admin resolves in Stripe, then the webhook updates the state; helper (14px `--ink-dim`) "Cette vue est en lecture seule. Traitez l'écart dans Stripe (rapprochement, remboursement) ou émettez un avoir." Rows older than 14 days show the line "En attente depuis plus de 14 jours" (aligned with D-17 alert).

## Surface C — PDF deltas (print contract from 13-UI-SPEC Surface C unchanged)

All mandatory mentions as extractable text (DOC-04 test extended to the credit note).
