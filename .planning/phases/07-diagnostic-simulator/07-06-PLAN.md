<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| translations content → server-rendered `<script type="application/ld+json">` | `t.simulateur.faq` strings are injected into raw HTML via `dangerouslySetInnerHTML`. This is the only `dangerouslySetInnerHTML` this phase introduces. |
| crawler / public internet → `/simulateur` | The route is deliberately indexable, so its server-rendered HTML is public. It must contain no secret, no internal identifier and no scoring weight. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-18 | Tampering | XSS via a closing-script sequence in FAQ copy breaking out of the JSON-LD tag | mitigate | Serialize exclusively through `buildJsonLdScript`, which replaces `<` with `\u003c` (the control `src/lib/serviceJsonLd.ts` was written for in Phase 6). `JSON.stringify` is forbidden in this file and the acceptance criteria assert its absence. |
| T-07-19 | Information Disclosure | Scoring weights or question branching logic exposed in the server-rendered HTML | accept | `layout.tsx` renders only FAQ copy; `page.tsx` renders only i18n copy. The weights live in a client bundle that is public by nature but carries no secret — the recommendation is a sales heuristic, not an access-control decision. |
| T-07-20 | Spoofing | `/simulateur` being indexed with the wrong canonical and cannibalising a service page | mitigate | `alternates.canonical` is pinned to `/simulateur` and `robots` is `{ index: true, follow: true }`; `layout.test.ts` asserts both. |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs zero packages. `graphify update .` is a local AST-only refresh with no registry fetch. Any `npm install` during execution is out of contract and must be stopped and reported, not auto-approved. |
</threat_model>
