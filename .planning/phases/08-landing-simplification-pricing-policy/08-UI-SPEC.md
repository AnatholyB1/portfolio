## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, dot indicators |
| sm | 8px | Compact inline spacing (badge gaps, pill padding) |
| md | 16px | Default element spacing, grid gaps (`.problem-grid`, `.reassure-grid` at 16-24px) |
| lg | 24px | Card internal padding gaps, `.upsell-grid`/`.svc-preview-grid` gaps |
| xl | 32px | Section-head gaps, `.sec-head` bottom margin components |
| 2xl | 48px | Sub-section breaks (`.svc-sec` vertical padding) |
| 3xl | 64px | Page-level breaks (`.svc-cta` vertical padding, `.contact-info` gaps ×n) |

Exceptions (already established site-wide, reuse as-is — do not invent new large-spacing values):
- Section vertical rhythm uses the existing `.sec` shell: `140px 0` desktop / `80px 0` mobile (`@media max-width:900px`). All new sections in this phase (Problems, Services Overview, Fonctionnement, Enjeux) MUST reuse the `.sec`/`.sec-head`/`.wrap` shell rather than custom padding.
- Interactive touch targets: 44px minimum height, already enforced on `.btn`, `.sim-option`, `.sim-nav .btn` — carry this forward to any new CTA buttons/cards in this phase (`.svc-preview-card` as a full-card link should have effective tap height ≥44px).
- `.phone-section`'s original `160px 0` padding is an outlier reserved for the *old*, feature-rich PhoneAgent layout. Since D-07 trims PhoneAgent to a short teaser, **use the standard `.sec` padding (140/80px) instead of `.phone-section`'s 160px** for the teaser — a short 2-3 line teaser inside 160px of padding looks visually empty.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (Manrope, `--font-body`) | 400 | 1.5 |
| Label | 11px (JetBrains Mono, `--font-mono`, uppercase, letter-spacing 0.15-0.18em) | 500 | 1.4 |
| Heading (h2, section titles) | clamp(40px, 6vw, 72px) (Space Grotesk, `--font-display`) | 500 | 0.95–1.15 (use `.sec-title`'s 0.95 for landing section heads; svc/faq headings in reused components already use 1.15-1.25 — keep as-is where reused verbatim) |
| Display (h1, hero/CTA-scale) | clamp(56px, 9vw, 144px) (Space Grotesk, `--font-display`) | 500 | 0.86–0.95 |

Only 2 weights in scope for this phase: **400 (regular — body copy, descriptions)** and **500 (medium — all headings, buttons, labels, numbered badges)**. The nav-brand logo's 700 weight is a fixed, pre-existing brand-lockup exception — do not introduce 700 anywhere else. Italic (`.it`) is a style variant of 400/500, not a separate weight.

## New/Modified Section Specs

### 1. Problèmes résolus (Step 1/6)
- **Reuse verbatim:** `ProblemSection.tsx`'s JSX structure and CSS (`.sec`, `.sec-head`, `.problem-grid`, `.problem-card`, `.pn`, `.problem-good`).
- **Content:** new `t.landing.problems` translation key (shape below), 3-4 items per D-05 (not 9, not 5-6). Exact wording is executor's discretion within D-05's examples ("invisible en ligne", "personne ne répond au téléphone", "image dépassée", "pas le temps de gérer les réseaux").
- **CTA:** single bottom CTA → `/simulateur` (D-06). Render as a `.btn.btn-primary` directly under `.problem-good` (new addition — `ProblemSection.tsx` currently has no CTA at all; add one `<a>` centered below the "good news" banner).
- **Recommended translation shape** (per RESEARCH.md Architecture Patterns, adopted as-is):
```typescript
problems: {
  num: string;
  title_l1: string; title_l2_it: string;
  intro: string;
  items: { n: string; title: string; desc: string }[]; // 3-4 items
  good_news: string;
  cta: string; // button label, e.g. "Tester le diagnostic"
}
```

### 2. Aperçu des services (Step 2/6) — NEW section
- **Purpose:** literal LANDING-01 requirement — "cartes renvoyant vers chaque page dédiée." Distinct from the Problems section (D-06 explicitly forbids per-card service links *there*; this section is where those links belong).
- **Layout:** `.sec`/`.sec-head` shell, heading e.g. "Nos services" (mirrors `/services` index tone but condensed — no price row, no popular badge, ever).
- **Card pattern:** reuse `.upsell-card` styling verbatim (background `--bg-2`, border `--line`, hover border `--ink`, padding 24px, border-radius 10px) plus `.un` (mono index label in `--acid`) for the numeral — these classes exist in `globals.css` (lines ~534-542) and are currently orphaned (`OptionsSection.tsx` unused). Each card: `.un` index (e.g. "01"), `<h4>` service name, `<p>` one-line tagline (reuse `t.services.pages.items[i].tagline`, already written and price-free from Phase 6 — do not write new tagline copy). Entire card is an `<a href="/services/{slug}">`.
- **Grid:** new `.svc-preview-grid` rule (9 items don't divide evenly into `.upsell-grid`'s 4-col layout) — `grid-template-columns: repeat(3, 1fr)` at ≥900px, `repeat(2, 1fr)` 600-899px, `1fr` below 600px. Gap 16-24px (reuse `.upsell-grid`'s 14px or round up to the 16px `md` token).
- **No bottom "view all" CTA required** — all 9 cards are shown directly (small enough grid; avoids adding a second `/services` link that would need its own LANDING-02 justification).
- **These 9 card-links are the CTA-table exception category** — see CTA Destination Table, row 4.

### 3. Fonctionnement (Step 3/6) — NEW section
- **Reuse verbatim:** `MethodologySection.tsx`'s component structure (GSAP `ScrollTrigger`-driven active-step rail — `gsap` is already a project dependency, no new install) and its CSS (`.method`, `.method-rail`, `.method-rail-active`, `.method-steps`, `.method-step`, `.ndot`, `.num-big`).
- **Content:** new `t.landing.method` key (do **not** reuse `t.services.method`, which is orphaned/price-adjacent legacy content) describing Sèvalys's general engagement process — 3-4 numbered steps, no price mention at any step (PRIX-01 applies here too since this is new landing copy). Example shape only (exact wording executor's discretion): "01 Diagnostic" → "02 Proposition sur mesure" → "03 Déploiement" → "04 Suivi & support."
- **No CTA in this section** — purely explanatory, consistent with the reused component's original design (no button inside `MethodologySection.tsx` today).

### 4. Enjeux (Step 4/6) — NEW section
- **Reuse verbatim:** `ReassuranceSection.tsx`'s structure and CSS (`.reassure-grid` — 2-col at ≥900px, `.reassure`, `.rn`).
- **Content:** new `t.landing.enjeux` key (do **not** reuse `t.services.reassurance`) — 3-4 numbered points framing what's at stake for a PME that doesn't act (e.g., competitors capturing search visibility, missed calls compounding, brand credibility erosion). No price mention (PRIX-01).
- **No CTA in this section** — purely explanatory, mirrors the reused component's original design.

### 5. PhoneAgent teaser (D-07/D-08)
- **Keep:** `.phone-badge`, `.live` dot, section wrapper.
- **Remove:** `.phone-features` list rendering (`pa.features` field/usage), the entire `<PhoneFlow>` sub-component and its scroll-listener (`onScroll`/`activeStep` state, `window.addEventListener('scroll', ...)`), and the `/demo` + `/services#phone-agent` CTAs.
- **Layout change:** since removing `PhoneFlow` empties the right column of `.phone-grid`, do **not** keep the 2-column grid for the teaser — collapse to a single centered column, `max-width: 640px`, and swap `.phone-section`'s `160px 0` padding for the standard `.sec` shell's `140px 0` / `80px 0` (see Spacing Exceptions above). Structure top-to-bottom: `.phone-badge` (with `.live` dot) → heading (`.sec-title` scale, reuse existing `pa.title_l1`/`title_l2`/`title_l3_it` fields) → 1-2 sentence paragraph (`.sec-intro` scale, 17px) → single `.btn.btn-primary` → `/services/agent-vocal-ia`.
- **Translation key impact:** `t.landing.phone.features`, `.cta_demo`, `.cta_more`, `.flow_label`, `.flow_rec`, `.flow_steps` all become dead fields — remove from the `Translations` interface and all 3 locale objects (do not leave orphaned price-adjacent/legacy fields per RESEARCH.md Pitfall #1's warning about silent guard gaps). `.cta_roi` is repurposed as the single teaser CTA label (repoint its href, per D-08).

### 6. Realisations bridge (D-10)
