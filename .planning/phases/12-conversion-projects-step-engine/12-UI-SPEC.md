# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: --auto (no questions asked). Sources: 12-CONTEXT.md (D-01..D-22), 12-RESEARCH.md, 10-UI-SPEC / 11-UI-SPEC (inherited), `src/app/portal.css`, `src/components/portal/client.css`, `src/components/admin/admin.css`, `src/components/admin/leads/leads.css`.

Scope: private surfaces only, French only, `noindex`, sober back-office. No cinema intro, no custom cursor, no GSAP, no scroll-reveal, no animation beyond 150-200 ms color/border transitions (disabled under `prefers-reduced-motion`). Prices are allowed in portal/admin but this phase shows none.

Screens covered:
1. Client portal, project page `/espace-client` (6-step timeline, who-waits panel, onboarding, files, useful links, presentation consent)
2. Admin projects table `/admin/projets`
3. Admin project sheet `/admin/projets/[id]`
4. Lead conversion dialog on `/admin/leads/[id]`

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner gap, timeline connector inset |
| sm | 8px | Compact spacing, field label-to-input gap, list item gap |
| md | 16px | Default element spacing, card gap, table cell padding |
| lg | 24px | Card padding, section padding inside a page |
| xl | 32px | Gap between page sections (`pt-main` gap), page padding on desktop |
| 2xl | 48px | Page top padding on desktop (`pt-main` >= 768px) |
| 3xl | 64px | Header height only |

Exceptions:
- Touch/click targets `min-height: 44px` (buttons, inputs, nav, pills, table row actions, checkbox label rows).
- Timeline marker 24px circle with 2px connector line (visual primitives, not layout spacing).
- 12px (multiple of 4, already used in `pt-lead-pill-menu`) allowed only for menu item horizontal padding and OTP-style grouping; do not introduce elsewhere.
- Layout widths: client content `max-width: 960px` (`ShellMain width="client"`), admin `1120px` (`width="admin"`), conversion dialog `560px`.

## Color

Inherited tokens only. No new colors. `--pt-border-strong: #6f6b64` for field/pill borders (3:1 on dark).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` #0A0B0C | Page background, `pt-readback` inner background |
| Secondary (30%) | `--bg-2` #111213 / `--bg-3` #16181a | Cards, header, table, dialog (bg-2); inputs, badges, pills, row hover (bg-3) |
| Text | `--ink` #ECEAE3 / `--ink-dim` #9A9690 / `--ink-faint` #5A5751 | Primary / secondary / disabled-decorative only. Never use `--ink-faint` for text that carries meaning (contrast too low): upcoming steps use `--ink-dim` labels, `--ink-faint` only for the hollow marker ring and connector |
| Accent (10%) | `--acid` #C4F542 (`--acid-soft` rgba(196,245,66,.12) for the current-step row tint) | See reserved list |
| Destructive / error | `--warm` #E07856 | Error messages, `aria-invalid` borders, corrective-fact confirm button text, failed upload row. Never for "waiting" states |

Accent reserved for (explicit, exhaustive):
1. Primary CTA buttons (`pt-btn-primary`): "Convertir et envoyer l'invitation", "Confirmer les informations de ma société", "Enregistrer mon accord", "Enregistrer le fait"
2. The marker of the **current** timeline step (filled acid circle, 24px) and its `--acid-soft` row tint
3. Active nav underline (portal Projet tab, admin Projets tab)
4. Keyboard focus ring (2px acid, offset 2px)
5. The 8px dot (`pt-lead-dot`) on admin rows and sheet header meaning "waiting on Sèvalys" (action required from the user of the admin)

Everything else (done steps, who-waits badges, "Attend le client", "Dormant", file badges) is neutral: `--bg-3` badge, `--pt-border-strong` border, `--ink` text, plus an icon and a text label. State is never conveyed by color alone.

## Screen Contracts

### S1. Client portal: project page (`/espace-client`)

Replaces the "Votre espace est en préparation" placeholder. Header: existing `ShellHeader variant="client"` (client name, sign-out). Nav: Projet (active, `aria-current="page"`), Documents and Paiements stay `aria-disabled` "bientôt" (phases 13/15). If the client has more than one project, a native `<select>` labelled "Projet" sits above the hero (hidden when exactly one project, D-10). Single column, `max-width: 960px`, sections separated by 32px, each in a `pt-card` (24px padding, 16px gap).

Section order (top to bottom, all visible from first login, D-12; onboarding never hides the others):

1. **Hero card**: H1 (Display 32px) = project title; helper line = offer name + "Démarré le {date}". Below: **Who-waits panel** (S1.1).
2. **Frise card** (S1.2): 6-step timeline.
3. **Onboarding card** (S1.3): shown expanded while step 1 is current/incomplete; collapses to a one-line summary with "Modifier mes informations" once complete.
4. **Fichiers card** (S1.4).
5. **Liens utiles card** (S1.5): hidden entirely when no links (no empty card).
6. **Accord de présentation card** (S1.6).
7. **Interlocuteur block** (existing contact block, kept at bottom).

#### S1.1 Who-waits panel
- Bordered block (`--bg-3`, 1px `--pt-border-strong`, radius 8px, padding 16px) with icon (20px) + two lines.
- Line 1 (Label 14px, `--ink-dim`): "En attente de" ; Line 2 (Heading 24px): "vous" / "Sèvalys" / (project done) "Rien, votre projet est livré".
- Line 3 (Body): the concrete expected action (see Copywriting), plus "Depuis {n} jour(s)" in Label 14px.
- Icons: client-side wait = `UserRound`; Sèvalys wait = `Clock`; done = `CircleCheck`.
- When waiting on the client and the action is the onboarding, the panel contains a primary CTA "Compléter mes informations" that scrolls/focuses the onboarding card heading (anchor link, `#onboarding`).

#### S1.2 Timeline (frise)
- Semantic `<ol aria-label="Avancement du projet">`, vertical at all widths (readable for a non-technical SME owner; no horizontal scroll). Each `<li>` row: marker column (24px) + text column; 2px connector (`--line-strong`) between markers; row min-height 44px; row gap 16px.
- Step labels (fixed): 1 Onboarding, 2 Cadrage et devis, 3 Contrat et acompte, 4 Production, 5 Recette, 6 Livraison et solde.
- Each row: step number in mono 14px ("01"), step name (Body 16px/500), one-line description (Label 14px `--ink-dim`).
- States (marker + text, three distinct non-color cues):
  - Done: 24px circle, `--ink` ring, `Check` icon 16px, name `--ink`; sr-only suffix ", terminée".
  - Current: filled `--acid` circle, row tint `--acid-soft`, `aria-current="step"`, name `--ink`, visible tag "En cours" (badge); sr-only suffix ", étape en cours".
  - Upcoming: hollow circle with `--ink-faint` ring, name `--ink-dim`; sr-only suffix ", à venir".
- Project complete (all 6 gates satisfied): all rows Done; hero panel shows done state; no current row.
- Done rows show completion date (Label 14px `--ink-dim`, "le 12 octobre 2026"); current row shows "depuis le {date}". Admin-only reasons and actor identities are never shown (Pitfall 4).
- No animation on state change; page re-renders on navigation.

#### S1.3 Onboarding card ("Confirmer, puis compléter")
- Heading (24px): "Vos informations". Helper: "Elles servent à préparer vos devis et contrats. Vos réponses sont enregistrées au fil de l'eau." Progress text (Label 14px) "{n} bloc(s) sur 5 complété(s)" with a `<progress>` (4px height track `--line-strong`, fill `--ink`; not acid) and sr-only duplicate.
- Five `<fieldset>` blocks, each with `<legend>` (Label) and a completion badge ("Complet" with `Check`, or "À compléter"). Single column on mobile, `pt-grid-2` from 768px. Labels above inputs, 8px label gap, 16px between fields; every input `min-height: 44px`, `autocomplete` hints set.
  1. **Votre société** (read-only readback via `pt-readback`/`pt-summary`: SIRET, raison sociale, adresse, forme juridique, pre-filled from `sv_clients.company`). Primary CTA "Confirmer les informations de ma société" (becomes a `pt-success` line "Confirmé le {date}" plus text button "Signaler une erreur" = `mailto:contact@sevalys.com` with prefilled subject; company data itself is not client-editable).
  2. **Signataire**: Nom complet*, Fonction*.
  3. **Contact du projet**: Nom, E-mail, Téléphone (optional; helper "Laissez vide si c'est le signataire.").
  4. **Facturation et TVA**: checkbox "L'adresse de facturation est celle de la société" (default checked); if unchecked reveal Adresse*, Code postal*, Ville*; TVA radio group (fieldset) "Numéro de TVA" (input, format validated, `FR` + 11 chars) / "Non assujetti à la TVA".
  5. **Votre projet**: Site web existant (URL `https:`), Réseaux sociaux (up to 4 URL rows, "Ajouter un réseau" text button), Objectif du projet (textarea, 4 rows, max 1000 characters with live counter "{n}/1000" Label 14px).
- Required fields marked "(obligatoire)" in the label text, not only an asterisk. Save behavior: each field saves on blur via server action (partial upsert); an `aria-live="polite"` status per card reads "Enregistrement…" then "Enregistré à {hh:mm}". No global submit button.
- Validation inline on blur, message under field (`pt-error` with `CircleAlert` icon), `aria-invalid="true"` + `aria-describedby`. On failed save: keep typed values, show error, focus stays.
- Completion: when signataire, TVA, billing address and company confirmation are all done, the card shows `pt-success` "Merci, votre onboarding est complet. Nous préparons votre devis." and collapses (details element, closed) with text button "Modifier mes informations". Further edits after completion save silently the same way.

#### S1.4 Files card
- Heading "Fichiers du projet". Primary-neutral action: `pt-btn-ghost` "Ajouter un fichier" (icon `Upload`) wrapping a visually hidden `<input type="file">`; helper under it: "25 Mo maximum par fichier. PDF, images, documents Office, archives zip et logos vectoriels (SVG, AI, EPS)." No drag-and-drop zone (keeps accessibility and scope small).
- Upload row while sending: filename, `<progress>` (value/max), text button "Annuler". States: "Envoi en cours…", success `pt-success` "{nom} ajouté", failure `pt-error` row (see Copywriting) with "Réessayer".
- List: `pt-table` (cards under 768px via `data-label`). Columns: Nom (with file-type icon `FileText`/`Image`/`Archive`), Déposé par ("Vous" / "Sèvalys"), Ajouté le, Taille ("2,4 Mo"), Action ("Télécharger", `pt-btn-text`, `Download` icon). Sorted newest first. Download triggers the server action that returns a signed link (120 s) and navigates with attachment disposition; button shows "Préparation…" while pending. No inline preview, ever (SVG risk). No delete in phase 12.
- Pending uploads older than 24 h are not listed.

#### S1.5 Useful links card
- Heading "Liens utiles". Plain list: link title (underlined `--ink`, `target="_blank" rel="noopener noreferrer"`, trailing `ExternalLink` icon 16px, sr-only " (nouvel onglet)") and host in Label 14px `--ink-dim`. Read-only for the client (D-15). Only `https:` URLs render as links.

#### S1.6 Presentation consent card
- Heading "Présentation de votre projet". Intro (Body): "Vous décidez si Sèvalys peut montrer ce projet. C'est facultatif et sans effet sur votre projet."
- Exact legal text shown in a bordered quote block (`pt-readback`), Body 16px, followed by Label 14px "Version {version}". Text is PROVISIONAL until legal review (blocker): the block must carry the constant `PRESENTATION_CONSENT.text` unchanged; a human-validation task precedes release.
- Not granted (default; never pre-checked): checkbox row (44px target) with label "J'ai lu le texte ci-dessus et j'accepte." + primary button "Enregistrer mon accord", disabled until the checkbox is checked.
- Granted: `pt-success` "Accord donné le {date}." + `pt-btn-ghost` "Retirer mon accord" (immediate, no confirm dialog: it is reversible and non-destructive; result line "Accord retiré le {date}." and the checkbox form returns).
- Stale text version (constant changed while page open): `pt-error` "Le texte a été mis à jour. Rechargez la page pour le relire avant de confirmer." with button "Recharger la page".
- Status messages in `aria-live="polite"`.

#### S1 states summary
| State | Treatment |
|-------|-----------|
| Loading | Server-rendered (`force-dynamic`), no skeletons; buttons show pending label and `disabled` during actions (`useActionState`) |
| No project yet (client without project) | Hero replaced by empty state (Copywriting) |

| No access | Existing `NoAccess` component |
| Offline/server error | `pt-error` banner at top of the affected card with retry text |

### S2. Admin projects table (`/admin/projets`)

Nav: `AdminNav` gains item `projets` ("Projets") between Leads and Entonnoir (`AdminNavItem = 'clients' | 'leads' | 'projets' | 'entonnoir'`). Page: `ShellMain width="admin"`, H1 "Projets" (Heading 24px), `pt-intro` helper: "{n} projet(s). Triez par colonne, filtrez par étape ou par blocage."

- **Filters bar** (reuse `pt-lead-filters`): select "Étape" (Toutes, 1 à 6 with names, "Terminé"), select "Blocage" (Tous, "Attend le client", "Attend Sèvalys", "Dormant"), text button "Réinitialiser les filtres". Filters are GET query params (shareable, no JS required); applied server-side.
- **Table** (`pt-table pt-admin-table`), columns: Client (link to sheet, underlined, shows company name; sub-line Label 14px `--ink-dim` = project title), Offre, Étape ("3/6 Contrat et acompte"), Qui attend (badge), Depuis (days, tabular-nums, "12 j"). Default sort: blocked-on-Sèvalys first, then Depuis desc.
- Sortable headers: `<th aria-sort>` containing a `<button>` (Label mono uppercase) with `ChevronUp/ChevronDown` icon on the active column; sort via query param.
- **Qui attend badge** (`pt-lead-badge`, neutral): "Client" with `UserRound`, "Sèvalys" with `Clock` plus the 8px acid dot, "Terminé" with `CircleCheck`. A separate neutral badge "Dormant" with `Moon` icon appended when no activity for 14 days (`DORMANT_AFTER_DAYS`), in addition to (not instead of) the waiting badge.
- Row click target is the Client link only; no whole-row click. Below 768px rows become cards (`data-label` on each td: "Client", "Offre", "Étape", "Qui attend", "Depuis").
- Empty (no projects): see Copywriting. Empty with filters: "Aucun projet ne correspond à ces filtres." + "Réinitialiser les filtres" text button.
- Pagination not needed (low volume); if > 50 rows reuse `pt-lead-pager`.

### S3. Admin project sheet (`/admin/projets/[id]`)

Back link `pt-back` "‹ Projets". Header row: H1 = client company name; sub-line = project title + offer; right side: waiting badge (+ acid dot if Sèvalys) and "Dormant" badge when relevant. Layout: `pt-lead-grid` (main column + side column; stacks under 768px, main first).

**Main column**
1. **Étape et faits** card:
   - Compact read-only timeline (same `pt-step-*` component as S1.2, admin variant adds the date and actor kind "Système / Admin / Client" per done step).
   - Status block: "Étape en cours : {n}/6 {nom}", "En attente de {client|Sèvalys}", "Depuis {n} jours" and the expected action text.
   - **Poser un fait** form (`pt-lead-form`): `<select>` "Fait à enregistrer" listing only fact types not yet effective, labelled in French (Devis accepté, Contrat signé, Acompte reçu, Production terminée, Recette signée, Solde reçu; `onboarding_completed` is system-only and not listed), optional textarea "Motif ou note (interne, 500 caractères max)", primary button "Enregistrer le fait". After success: `pt-success` "Fait enregistré. L'étape est maintenant {nom}." and the client mail status line "E-mail envoyé au client" / "E-mail en attente d'envoi" / "Échec de l'envoi, il sera retenté".
   - Posting a fact "out of order" is allowed; show `pt-warn` helper under the select when the chosen fact does not match the current gate: "Ce fait est en avance : l'étape ne changera qu'une fois les faits précédents enregistrés."
   - **Journal des faits** (reuse `LeadJournal` look): chronological list, newest first: date, fact label, actor kind, motif (admin-visible), and for corrections "Annule : {fait annulé}". Corrected facts are shown struck-through-free: tagged badge "Annulé" (text), never removed. Each effective fact row has text button "Annuler ce fait" (opens corrective panel).
   - **Annuler ce fait** (destructive-ish, append-only): inline `pt-lead-panel` (like `LostPanel`): required textarea "Motif de la correction (10 à 500 caractères)", button "Confirmer l'annulation" in `--warm` text with `--warm` border (ghost style), text button "Garder ce fait". Copy in Copywriting. After confirm: step recalculated, history kept.
2. **Fichiers** card: same table as S1.4 plus "Déposé par" shows "Client" / "Sèvalys" and same upload control (admin can upload, D-14) and download. No delete.

**Side column**
3. **Informations** (`pt-summary` dl): Client, SIRET, Offre, Titre du projet, Début, Contact (name, e-mail, phone from onboarding or invited member), "Dernière activité : {date} ({n} j)".
4. **Onboarding** (read-only summary): list of the 5 blocks with Complet / À compléter badges and values (signataire, TVA statut, adresse de facturation, objectif). Not editable by admin in phase 12.
5. **Accord de présentation**: read-only state "Accord donné le {date} (version {v})" or "Aucun accord" or "Accord retiré le {date}"; history disclosure `<details>` "Historique" listing every line.
6. **Liens utiles**: list (title, host, `ExternalLink`) + add form (`pt-lead-form`): "Titre" (text, max 80), "Adresse (https://…)" (url, `https:` only), button `pt-btn-ghost` "Ajouter le lien". Admin-only add; no edit/delete in phase 12 (append only) unless planner adds; if added, removal needs no confirm dialog but shows a result line.

### S4. Lead conversion dialog (`/admin/leads/[id]`)

- **Trigger**: `pt-btn-primary` "Convertir en client" (icon `UserPlus`) in the lead page header actions, next to `StatusPill`. Visibility rules (D-03/D-04):
  - Status Qualifié, RDV, Devis envoyé, Signé and not converted: button enabled.
  - Status Nouveau or Perdu: button shown disabled (`aria-disabled`, not removed) with helper text adjacent: "Convertible à partir de « Qualifié »." For Perdu: "Rouvrez d'abord le lead pour le convertir."
  - Already converted: replace button by a neutral badge "Client converti" + link "Voir le projet" (to `/admin/projets/[id]`); no second conversion.
- **Dialog**: native `<dialog>` opened with `showModal()`, `aria-labelledby` = title, backdrop `rgba(10,11,12,.8)`, panel `--bg-2`, 1px `--line-strong` border, radius 12px, padding 24px, `max-width: 560px`, full width minus 32px on mobile, internal scroll if taller than viewport. Esc and "Annuler" close; focus moves to first field on open and returns to the trigger on close; backdrop click does not close while submitting.
- **Title** (Heading 24px): "Convertir en client". Helper: "Cela crée le client, son premier projet et envoie l'invitation à son espace."
- **Fields** (reuse existing invite form lookup + `readback` components `InviteForm`, no duplicate implementation): Nom du contact* (prefilled from most recent contact), E-mail* (prefilled, editable), SIRET* with "Rechercher l'entreprise" ghost button and `pt-lookup-status`, company fieldset (raison sociale, adresse, forme juridique, auto-filled from lookup, `pt-company`), Offre* (`<select>` of existing offers, preselected from the lead's interest when known), Titre du projet* (default "Projet {raison sociale}", max 80).
- **Inline notices** (`pt-warn`): existing SIRET: "Ce SIRET correspond à un client existant. Il sera réutilisé et un nouveau projet y sera ajouté." ; e-mail already admin/member: blocking `pt-error` (see Copywriting).
- **Actions** (right-aligned on desktop, stacked full-width on mobile, primary first in DOM order is last visually: Annuler left, primary right): `pt-btn-text` "Annuler", `pt-btn-primary` "Convertir et envoyer l'invitation". During submit: primary disabled with label "Conversion en cours…"; double click impossible.
- **Success**: dialog closes; lead page shows `pt-success` banner "Client créé. Invitation envoyée à {email}." plus links "Voir le projet". If the mail failed but conversion succeeded: `pt-warn` "Client créé, mais l'invitation n'a pas pu partir. Elle sera retentée automatiquement ; vous pouvez aussi la renvoyer depuis la liste des clients." (conversion is never rolled back for a mail failure).
- **Failure**: dialog stays open, `pt-error` at top of dialog (`role="alert"`), values preserved.

## Interaction & Accessibility Rules (all screens)

- Keyboard: every control reachable, visible acid focus ring; dialog traps focus; tables sortable by buttons, not click-on-th.
- `aria-live="polite"` for save/status messages, `role="alert"` for errors blocking an action.
- Touch targets >= 44px; body text >= 16px (14px only for labels/metadata).
- Contrast: text on `--bg-2`/`--bg-3` uses `--ink` or `--ink-dim` only (>= 4.5:1). `--ink-faint` never for text.
- No color-only meaning: every state has icon or text.
- Dates rendered in `fr-FR` long form ("12 octobre 2026"), times "14:05"; durations "3 jours", "1 jour". All server-rendered in `Europe/Paris`.
- Reduced motion: no animations at all; transitions disabled by existing media query.
- Guards (source-level tests, pattern `layout.test.ts`): no price/euro strings in new copy, no GSAP/cursor imports, `noindex` kept, no `--ink-faint` as text color in new CSS.
