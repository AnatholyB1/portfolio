    Create `src/app/api/simulateur/route.ts` exporting an async `POST` handler. Do not export `GET`, `PUT`, `PATCH` or `DELETE` - this endpoint is POST-only.

    The handler must run these steps in exactly this order:

    1. Parse the JSON body with a `.catch(() => null)` guard, mirroring `contact/route.ts` line 17. On a null body, return `{ error: 'invalid_payload' }` with status 400.
    2. Call `isSpamSubmission(raw)` from `@/lib/prospects-schema`. If it returns true, return `NextResponse.json({ ok: true })` immediately - no insert, no email, no distinct error code and no distinct status. This silent-reject is deliberate: returning a 4xx or a different body would tell a scripted bot it was detected. Add a comment saying so. This check MUST come before validation and before any Supabase or Resend call, because CRM-03's success criterion is that bot submissions are rejected *before being written to the database*.
    3. Run `prospectSchema.safeParse(raw)`. On failure, return `{ error: 'invalid_payload' }` with status 400.
    4. Derive `ipHash`: read the first comma-separated entry of the `x-forwarded-for` request header, trim it, and hash it with `createHash('sha256')` from `node:crypto`, hex digest. If the header is absent, set `ipHash` to null. Never store or log the raw IP - the hash exists only for abuse correlation, and storing the raw address would add unnecessary PII to a table governed by a 12-month consent window (D-04).
    5. Insert via `createServiceRoleClient().from('prospects').insert({...})`, mapping each field explicitly from the zod-parsed object: `nom`, `email`, `telephone`, `reponses_diagnostic` from `reponsesDiagnostic`, `services_recommandes` from `servicesRecommandes`, `consentement_rgpd` from `consentementRgpd`, and `ip_hash` from the derived hash. Never spread the raw body or the parsed object into `insert()` - explicit mapping is the mass-assignment mitigation and matches every existing insert in this repo. Do not chain `.select().single()`; the response body has no use for the inserted row. Do not send `id` or `created_at` - both are database-generated.
    6. On insert error, `console.error('[api/simulateur] insert failed', error)` and return `{ error: 'insert_failed' }` with status 500. Do not include the Postgres error message in the HTTP response body - it can leak schema details to an unauthenticated caller.
    7. On insert success, send exactly ONE Resend email: `from: 'Sevalys <contact@sevalys.com>'` (use the accented spelling exactly as it appears in `contact/route.ts`), `to: 'contact@sevalys.com'`, `subject: 'Nouveau prospect - simulateur'`, and an HTML body listing Nom, Email, Telephone and Services recommandes. Unlike `contact/route.ts` this route sends a single email, not a `Promise.all` pair - no confirmation email to the prospect was requested in CONTEXT.md. Define a local `escapeHtml` helper duplicating the 4-replace implementation from `contact/route.ts` rather than importing from or refactoring that file (per 05-RESEARCH.md, `api/contact` must not be touched in this phase), and apply it to every prospect-supplied string interpolated into the HTML, including each entry of the services array. Unescaped prospect input in an internal notification email is a stored-XSS vector against whoever opens it.
    8. If the Resend call returns an error, `console.error('[api/simulateur] Resend send failed', result.error)` and return `{ error: 'notification_failed' }` with status 500 - but note in a comment that the row was already persisted, so the prospect is not lost.
    9. On full success, return `NextResponse.json({ ok: true })`.

    Do not add `export const runtime = 'edge'` - `node:crypto` requires the Node runtime, which is the default.

    Reject a `reponsesDiagnostic` payload only through the schema; do not add extra ad-hoc validation in the route.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser / any HTTP client -> `POST /api/simulateur` | Unauthenticated public endpoint; the entire JSON body and every request header are attacker-controlled |
| Route Handler -> Supabase (service_role) | A credential that bypasses RLS entirely crosses from env into a request-handling code path |
| Route Handler -> Resend -> internal inbox | Prospect-supplied text is rendered as HTML in a Sevalys team member's mail client |
| Build pipeline -> client bundle | Next.js inlines `NEXT_PUBLIC_*` env vars into shipped JavaScript |

## STRIDE Threat Register
