## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → invite logic | admin input (email, SIRET, edited company data) |
| server → recherche-entreprises API | untrusted third-party JSON |
| server → Supabase Auth admin | creates users on a shared project |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-30 | Spoofing | invite.ts (pre-account takeover) | mitigate | sv_find_auth_user check; existing accounts never reused/deleted; new users created passwordless + email_confirm |
| T-10-31 | Elevation of privilege | role exclusivity | mitigate | app checks sv_admins first + DB trigger sv_role_conflict + rollback (D-04) |
| T-10-32 | Tampering | SIRET API response | mitigate | exact SIRET match, field whitelist, zod on admin-edited snapshot |
| T-10-33 | Information disclosure | dirigeants personal data | mitigate | never persisted (whitelist; test asserts absence) |
| T-10-34 | Elevation of privilege | inviteClient callable without admin | mitigate | server-only module; plan 10-11 action calls requireAdmin() (getUser-verified) before inviteClient |
| T-10-34b | Elevation of privilege | scripts/sv-add-admin.mjs | mitigate | requires the service_role key held only by the owner locally; never imported by the app (grep criterion); dry run unless --yes; refuses client members (D-04); passwordless creation only |
| T-10-34c | Denial of service | single-admin lockout | mitigate | documented recovery script adds a second admin (user decision 2026-10-02) |
