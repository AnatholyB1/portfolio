# WCAG 2.2 AA review - private area (/connexion, /auth/confirm, /espace-client, /admin, 2 emails)

Method: static review of CSS/TSX/email templates, contrast computed in `contrast.js` (same folder) from the hex tokens, plus the desktop/mobile screenshots. No screen reader or real browser was run, so SR behaviour is inferred from markup and marked "(inferred)". Layout estimates (header squeeze, nav overflow, email code width) are arithmetic and need a browser or mail-client check.

## Executive summary
1. Contrast is excellent for ink, ink-dim, warm, acid and the emails' main text (6.2:1 to 16.5:1), but `--ink-faint` (#5A5751) carries real content at 2.5-2.7:1: field labels, "Retour au site", table headers, placeholder, disabled nav.
2. Borders of inputs, OTP cells and ghost button are 1.2-1.3:1 against their backgrounds (input fill vs card 1.05:1). Fails 1.4.11. In the screenshot the empty email field is only findable once focused.
3. Layout bug with a11y impact: forms inside `.pt-card` have no spacing. The email input and "Recevoir mon code" touch (screenshot: input bottom about y=330, button top about y=328). On the code step everything is stacked flush and the two text buttons sit side by side with 0 gap.
4. The code step keeps the h1 "Connexion" and the stale helper "Saisissez l'adresse e-mail..." above a second heading "Saisissez votre code".
5. Keyboard: autofocus on the OTP input works and the focus ring is solid (acid 14.7:1, 2px + 2px offset). But the SIRET blur-lookup inserts the readback panel after focus has already moved to the submit button, and the resend button is `disabled` during the countdown, so it is unreachable and never announced.
6. The mobile table uses `display:block` on table/tr/td, which strips table semantics in Chrome/Safari and the major screen readers.
7. Emails: no head/charset/title/color-scheme; the 8-digit code is about 230px wide at 32px Courier + 0.3em spacing and overflows the box below about 340px viewports; the invite footnote is 2.60:1.
8. Many things are right: lang="fr", landmarks, labelled inputs, autocomplete=email and one-time-code, inputmode, one real OTP input, 44px targets, reduced-motion handled, custom cursor/intro off on private paths.

## Passes
- `<html lang="fr">` (root) and `lang="fr"` in both email documents.
- Landmarks: one `<main>` per page, header/footer at body level, `<section aria-labelledby>`; h1 on every page; admin h1 > h2 > h3 in order.
- Labels via for/id on all inputs; `autocomplete="email"` + `inputmode="email"` on login (1.3.5); `autocomplete="off"` on admin fields is justified (client data, not the user's own).
- OTP: single real input (paste, SMS autofill, password managers work), one-time-code, numeric, digits filtered, cells `aria-hidden` so digits are not read twice, accessible name present.
- Focus: visible 2px acid outline, 2px offset on links, buttons, inputs; 14.7-15.5:1; container-level ring for the OTP; no outline removal without replacement; autofocus puts focus in the email field, then in the OTP field after the step change.
- Targets: inputs, OTP area, buttons, nav items `min-height:44px` (2.5.8 and 2.5.5 pass). The 12px "Retour au site" link has about an 18px line box but is isolated, so 2.5.8 passes by spacing.
- Reflow at 320px (from CSS): card `width:100%; max-width:400px`, OTP grid `minmax(0,1fr)` with `clamp(22px,7vw,32px)` digits, cells about 26px wide, no fixed widths, admin grid collapses below 768. The mobile screenshot clipping is an artifact; there is no overflow source in the card CSS.
- `prefers-reduced-motion` disables transitions (portal.css:481-488); no animations otherwise; custom cursor and cinema intro are skipped on private paths (ClientProviders.tsx).
- Errors: `--warm` 6.24:1 plus an icon (not colour only); live regions exist before injection (reliable); `aria-describedby` on email, OTP, SIRET; SIRET status is a pre-existing polite live region.
- Pending states change the label and prevent double submit.
- Emails: real text fallback (code on its own line, raw URL), no images or tracking, underlined link, presentation tables, h1 in the invite, CTA 16.49:1, code digits 15.46:1.

## Top 5 fixes by impact
1. One CSS rule giving `.pt-card form` a flex column with `gap:16px` (A-3).
2. Replace `--ink-faint` text with at least 4.5:1 and raise input/OTP/ghost borders to at least 3:1 (A-1, A-2): the two largest measured failures (2.5-2.7:1 and 1.2-1.3:1).
3. Make the code step a proper step: new h1/helper, remove the stale instruction, status region, visible label and active-cell highlight on the OTP (A-4, A-8).
4. Resend button `aria-disabled` + start/end announcements, and the SIRET flow with the readback group present before focus moves and no overwrite of edits (A-6, A-5).
5. Keep table semantics on mobile with explicit ARIA roles and a table name (A-10); fix email robustness: head/charset/color-scheme, the 2.60:1 footnote, the 230px code overflow (E-1, E-2, E-3).
