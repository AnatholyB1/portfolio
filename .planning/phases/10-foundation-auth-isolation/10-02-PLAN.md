<interfaces>
Database contract created here (later plans call these EXACT names):

Tables (schema public), all RLS on, `revoke all ... from anon, authenticated`:
- sv_tenants(id uuid pk, name text not null, created_at timestamptz) ; seeded row id '5e7a1750-0000-4000-8000-000000000001', name 'Sèvalys'
- sv_admins(user_id uuid pk -> auth.users on delete cascade, tenant_id uuid not null default '5e7a1750-0000-4000-8000-000000000001' -> sv_tenants, email text not null, created_at)
- sv_clients(id uuid pk default gen_random_uuid(), tenant_id uuid not null default (seed id) -> sv_tenants, name text not null check trimmed length 1..200, siret text not null unique check '^[0-9]{14}$', siren text generated always as (left(siret,9)) stored, company jsonb, company_source text not null default 'api' check in ('api','manual'), created_by uuid -> auth.users on delete set null, created_at)
- sv_client_members(client_id uuid -> sv_clients on delete cascade, user_id uuid -> auth.users on delete cascade, invited_email text not null, role text not null default 'member' check in ('member'), created_at, primary key (client_id, user_id), unique (user_id))
- sv_throttle(key text, window_start timestamptz, hits integer not null default 0, primary key (key, window_start)) -- no grants at all

Grants: `grant select on sv_admins, sv_clients, sv_client_members to authenticated` only. No insert/update/delete grant or policy for anon/authenticated (writes are service_role only in phase 10).

Schema sv_private (not exposed by PostgREST): `revoke all on schema sv_private from public, anon; grant usage on schema sv_private to authenticated;`
- sv_private.is_admin() returns boolean  (stable, security definer, search_path '')
- sv_private.client_ids() returns setof uuid  (stable, security definer, search_path '')
- sv_private.enforce_admin_exclusive() trigger fn (before insert/update on sv_admins: raise exception 'sv_role_conflict' using errcode 'P0001' if user_id in sv_client_members)
- sv_private.enforce_member_exclusive() trigger fn (before insert/update on sv_client_members: same if user_id in sv_admins)

Policies (all `to authenticated`):
- sv_admins_self_read: select using (user_id = (select auth.uid()))
- sv_clients_read: select using ((select sv_private.is_admin()) or id in (select sv_private.client_ids()))
- sv_members_read: select using ((select sv_private.is_admin()) or user_id = (select auth.uid()))
- sv_tenants: no policy (nobody but service_role reads it)

Service-role-only RPC functions (schema public so PostgREST/supabase-js `.rpc()` can call them; security definer; set search_path = ''; `revoke all on function ... from public, anon, authenticated; grant execute ... to service_role`):
- public.sv_login_allowed(p_email text) returns boolean  -- true iff an auth.users row with lower(email)=lower(trim(p_email)) has a row in sv_admins or sv_client_members
- public.sv_throttle_hit(p_key text, p_window_seconds integer, p_max integer) returns boolean  -- upsert hit in the current window bucket (date_bin or floor(epoch/window)), returns true when hits <= p_max (allowed), deletes buckets older than 1 day opportunistically
- public.sv_session_age_ok(p_session_id uuid, p_max_days integer default 30) returns boolean  -- exists(select 1 from auth.sessions where id = p_session_id and created_at > now() - make_interval(days => p_max_days))
- public.sv_find_auth_user(p_email text) returns table(id uuid, last_sign_in_at timestamptz)  -- lookup by lower(email)

| T-10-05 | Elevation of privilege | sv_admins | mitigate | no insert/update grant or policy for authenticated; seed only via migration (D-05); roles never from metadata (D-06) |
