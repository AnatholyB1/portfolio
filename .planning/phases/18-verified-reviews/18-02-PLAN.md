  <name>Review token derivation and submission schema</name>
  <files>src/lib/reviews/token.ts, src/lib/reviews/token.test.ts, src/lib/reviews/schema.ts, src/lib/reviews/schema.test.ts</files>
  <behavior>
    Token:
    - reviewSecret({REVIEW_TOKEN_SECRET: 'x'.repeat(31)}) -> null; 32 chars -> the value; undefined -> null
    - deriveReviewToken(id, s) is deterministic, 43 chars, matches /^[A-Za-z0-9_-]{43}$/; different id or secret -> different token
    - hashReviewToken(t) matches /^[0-9a-f]{64}$/ and equals createHash('sha256').update(t).digest('hex')
    - isWellFormedReviewToken: rejects '', 65-char string, 'abc<def', 'a b', non-strings; accepts a derived token
    Schema:
    - valid minimal input (rating 3, body 20 chars, firstName 'Marie', displayMode 'first_company', consent true) parses
    - rating 0, 6, 2.5, missing -> error code 'rating'
    - body of 19 trimmed chars -> 'body_short'; 2001 chars -> 'body_long'
    - body or title containing '<', '>', 'http://', 'https://', 'www.' (case-insensitive) -> 'markup_or_link'
    - body with control char \u0007 -> 'markup_or_link'; newlines \n allowed
    - consent false or missing -> 'consent'
    - displayMode 'first_initial' without lastInitial or with 2 letters -> 'initial'; person modes without firstName -> 'first_name'; 'company_only' needs no first name
    - the SAME body passes regardless of words like 'nul', 'déçu', 'mauvais' (no opinion filtering, D-05): test with a 1-star negative body and a 5-star positive body
    - firstName of 41 trimmed chars -> 'first_name'; a 40-char firstName passes
    - firstName '<b>Marie', 'Marie http://x', 'www.x.fr' or containing \u0007 -> 'markup_or_link'
    - lastInitial '1', '<', 'ab' -> 'initial'; lastInitial 'é' passes
    - composeDisplayName('first_company','Marie','', 'Café Dupont') === 'Marie, Café Dupont'; ('first_initial','Marie','d','X') === 'Marie D.'; ('company_only','', '', 'Café Dupont') === 'Café Dupont'
  </behavior>
  <implementation>
    Follow the unsubscribeToken.ts pattern for token.ts (fixed-string errors, no logging of token values). schema.ts uses zod v4 (`import { z } from 'zod'`), uses one shared `hasMarkupOrLink(value)` check (`<`, `>`, http(s)://, www., control characters; newlines allowed only in body) for body, title and firstName, bounds firstName to 1..40 and lastInitial to one letter, maps issues to the field codes rating, title_long, body_short, body_long, markup_or_link, first_name, initial, consent, and exports REVIEW_FIELD_ERRORS with the exact UI-SPEC French copy (e.g. 'Choisissez une note de 1 à 5.', 'Votre avis doit faire au moins 20 caractères.', 'Les liens et le balisage ne sont pas acceptés dans un avis. Retirez-les puis réessayez.', 'Cochez la case pour que votre avis puisse être publié.'). Per D-05 the only content checks are technical (length, markup, links, control characters).
  </implementation>
</feature>
