# Phase 18 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: non-interactive auto. Decisions come from 18-CONTEXT.md (D-01..D-15) and 18-RESEARCH.md; remaining choices use defaults consistent with the existing design system and are marked (default).

Surfaces covered:
1. `/avis/[token]` : review form + thank-you + invalid-link state (private, noindex, `portal.css` / `pt-*` look, same as `/desinscription`)
2. `/avis` : public list (indexable, Navbar + Footer, marketing-site look like `mentions-legales`)
3. Home excerpt `AvisExcerpt` (client component, 2-3 recent reviews, between `Partners` and `ContactSection`)
4. `/politique-des-avis` : long-form policy page (Navbar + Footer, like `mentions-legales`)
5. `/admin/avis` : admin list, hide / unhide / reissue (back-office `pt-*` look, `admin.css` patterns)
6. Footer link addition

## Spacing Scale

Declared values (multiples of 4), identical to the existing system:

| Token | Value | Usage |

| sm | 8px | Label to field, inline meta separators |

## Typography

Four sizes, two weights, same as the private-space contract (`portal.css`): 14 / 16 / 24 / 32, weights 400 and 500.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (review text, policy paragraphs, helper, messages) | 16px | 400 | 1.5 |
| Label (field labels, meta line: author, date, "Avis vérifié", mono eyebrow) | 14px | 500 | 1.5 |
| Heading (card title of a review, policy section h2, form heading, admin section) | 24px | 500 | 1.2 |
| Display (page h1: "Avis clients", "Politique des avis", thank-you title) | 32px | 500 | 1.2 |

Notes:
- Font families: Display (Space Grotesk) for Heading/Display, Body (Manrope) for Body/Label. Mono (JetBrains Mono, 14px, weight 500, uppercase, letter-spacing 0.18em via existing `.label`) only for the eyebrow `// AVIS VÉRIFIÉS` and the rating figure "4/5" text.
- Display letter-spacing -0.02em (as `pt-display`). Minimum body size 16px on mobile for all form inputs (avoids iOS zoom).
- Longest line: review body max-width 68ch.

## Color

Existing palette only (PRODUCT.md constraint). No new hex except the already-defined scoped `--pt-border-strong: #6f6b64`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` #0A0B0C | Page background, form page background |
| Secondary (30%) | `--bg-2` #111213 (borders `--line` #1F1F1F) | Review cards, form card, excerpt cards, admin rows, thank-you card |
| Accent (10%) | `--acid` #C4F542 | See reserved list below |
| Destructive | `--warm` #E07856 | Validation errors and the "Masquer cet avis" confirm button only |

Text: `--ink` #ECEAE3 primary, `--ink-dim` #9A9690 secondary (meets AA on bg), `--ink-faint` #5A5751 only for non-essential decoration (never for text that carries meaning).

Accent reserved for:
1. Primary submit button "Publier mon avis" (`pt-btn-primary`)
2. Filled rating glyphs (selected value and displayed rating on cards)
3. Focus ring on every interactive element (2px `--acid`, offset 2px)
4. Links inside policy text and "Lire la politique des avis" link (underlined)
5. The mono eyebrow `// AVIS VÉRIFIÉS`
6. Admin "Lever le masquage" and "Réémettre le lien" primary actions are NOT accent (they use `pt-btn-ghost`); only the form submit uses accent.

Google button (REV-02): `pt-btn-ghost` (neutral outline, `--pt-border-strong`, ink text). It must never be accent-filled, to avoid steering emphasis, and must be visually identical for every rating.

Warm is never used for "negative review" styling. A 1-star review card looks exactly like a 5-star card except for the number of filled glyphs.

## Layout and Components

### 1. `/avis/[token]` (private form page)
- Layout copied from `desinscription/layout.tsx` (`pt-root`, `robots noindex`, `referrer no-referrer`), page `force-dynamic`. No Navbar, no cinema intro, no cursor, no GSAP, no analytics.
- `AuthCard` centered, `pt-card` max-width 440px on the `pt-auth` shell; the review form uses a wider variant: `pt-card` max-width 640px (default).
- Header inside card: `pt-brand` mark, h1 (Display) "Votre avis sur votre projet", helper line with the project title and company name (from link state): "Projet : {projectTitle}".
- Field order (single column, 16px gap):
  1. Note (required) : radiogroup of 5 buttons.
  2. Titre (optional) : `pt-input`, maxlength 100, helper "Facultatif".
  3. Votre avis (required) : textarea, min-height 160px, minlength 20, maxlength 2000, live counter in `pt-helper` ("{n} / 2000"), below minimum shows "Encore {k} caractères minimum" as plain helper (not error) until blur.
  4. Affichage du nom : 3 radios (default "Prénom + société"); fields "Prénom" (required) and, when mode is "Prénom + initiale", "Initiale du nom" (1 char, required). Live preview line: "Affiché publiquement : Marie, Café Dupont".
  5. Consentement (required) : checkbox, label "J'accepte que mon avis soit publié sur le site de Sèvalys, avec l'affichage du nom choisi ci-dessus."
  6. Link "Lire la politique des avis" (D-13) directly above the submit button, opens same tab.
  7. Submit `pt-btn-primary` full width on mobile, auto width from 640px.
- Rating control (`ReviewRatingInput`): `role="radiogroup"` with `aria-label="Note de 1 à 5"`, five `<button role="radio" aria-checked>` 44x44px, glyph = lucide `Star` 24px, filled `--acid` up to the selected value, outline `--pt-border-strong` otherwise. Each has `aria-label="{n} sur 5"`. Arrow keys move and select, Home/End jump, Tab enters group once (roving tabindex). Visible text echo next to the group: "{n} sur 5" (label role) so state does not rely on color. No default selected value, no hover preview that biases a value, nothing branches on the value afterward.
- States: idle, field error (inline `pt-error` under the field + `aria-invalid="true"` + `aria-describedby`), submitting (button disabled, label "Publication en cours…", `pt-status` live region), server rejection (summary `pt-error` at top with `role="alert"`, states the technical rule, see Copywriting), rate-limited, thank-you (replaces the card content on the same URL via redirect to `?merci=1`-style state; token not shown again).
- Server-side technical rules shown to the user are neutral: length, "les liens et le balisage ne sont pas acceptés". Never a message about tone or rating.

### 2. Thank-you state
- Same card. Display title "Merci pour votre avis", helper "Votre avis est publié sur la page Avis.", then a link "Voir la page Avis".
- Google block (single component `ReviewThankYou`, props: `googleUrl` only, NO rating prop): neutral paragraph + `pt-btn-ghost` anchor `target="_blank" rel="noopener noreferrer"`, label "Publier aussi sur Google", sr-only suffix " (s'ouvre dans un nouvel onglet)". Same markup, same label, same order for ratings 1 to 5 (tested). No wording suggesting reward, offer, or "if you are satisfied".
- If `REVIEW_GOOGLE_URL` is invalid, the Google block is omitted entirely (never a disabled button) and the rest of the page is unchanged.

### 3. Invalid / used / expired link state
- Single generic state for all four cases (no leak, D-09): `pt-card` with heading "Ce lien n'est plus valide", helper text, `mailto` link. Same HTTP status and markup for every case. No form is rendered.

### 4. `/avis` (public list)
- Navbar + Footer, `min-h-screen`, content in `.wrap` max-width 800px centered (reading column), page padding top 128px (existing), bottom 64px.
- Header: mono eyebrow `// AVIS VÉRIFIÉS`, h1 (Display) "Avis clients", intro paragraph (Body, `--ink-dim`): explains verification in one sentence + inline link "Politique des avis" (D-13).
- List: vertical stack of `ReviewCard`, 32px gap, newest first. No pagination in v1 (default: cap 50 via RPC, then "Voir les avis précédents" is out of scope). No average, no count, no aggregate rating anywhere (D-04).
- `ReviewCard` (`<article>`, `--bg-2`, `--line` border, 12px radius, 24px padding, 16px inner gap):
  - Row 1: rating glyphs (5 lucide Star 20px, filled/outline, `aria-hidden`) + text "{n} sur 5" (Label) ; `<span class="sr-only">Note : {n} sur 5</span>` available to screen readers.
  - Optional title (Heading 24px).
  - Body (Body 16px, `--ink`, `white-space: pre-line`, rendered as React text only).
  - Meta row (Label 14px, `--ink-dim`): display name, separator " · ", `<time datetime>` "12 octobre 2026", badge "Avis vérifié" (text with lucide `BadgeCheck` 16px, `--ink-dim`, not accent-filled).
  - Experience date shown only when present: "Projet livré en octobre 2026".
- Each card has an `id="review-{id}"` anchor (matches JSON-LD `@id`).
- Policy link also repeated at the bottom as a boxed `pt-card` row: "Comment nos avis sont collectés et modérés" + link (D-13).
- JSON-LD: one `<script type="application/ld+json">` per published, non-hidden review, rendered only here; content must be visible in the card (rating, title, body).
- Empty state: see Copywriting. No placeholder cards, no fake reviews.

### 5. Home excerpt `AvisExcerpt`
- Client component, fetches `/api/avis/recent`; renders nothing while loading, on error, or when 0 reviews (no layout shift reserve, no skeleton). Home cinema intro and price guard untouched.
- Section: `.wrap`, vertical padding 48px, top `border-t`. Eyebrow `// AVIS VÉRIFIÉS`, h2 (Heading 24px) "Ce que disent nos clients".
- Grid: 1 column on mobile, 2 columns at 768px, 3 at 1100px when 3 reviews; 24px gap. Compact card: rating glyphs + "{n} sur 5", body clamped to 5 lines (`line-clamp-5`), then name and date. No title in compact card.
- Footer row of the block: link "Voir tous les avis" (`--ink`, underlined, arrow lucide `ArrowRight` 16px) and link "Politique des avis" (D-13). Neither link is a filled button, to keep home CTAs (simulateur, contact) dominant.
- Reduced motion: no entrance animation (default, no GSAP reveal). If the surrounding sections use a reveal, this block simply appears without it.

### 6. `/politique-des-avis`
- Same shell as `mentions-legales` (Navbar, max-width 3xl, `Section` pattern with h2 + bottom border, 40px between sections). Eyebrow `// TRANSPARENCE`, h1 "Politique des avis".
- Required sections, in order (D-12): 1 Qui peut déposer un avis ; 2 Comment un avis est vérifié ; 3 Publication sans filtrage ; 4 Refus technique d'une soumission ; 5 Modération limitée à la légalité (render the four reasons as a list) ; 6 Journal et notification de l'auteur ; 7 Aucune contrepartie, aucun filtrage de la demande ; 8 Affichage du nom, dates et consentement ; 9 Lien Google ; 10 Durée de conservation ; 11 Signaler un doute (mailto).
- French only. Retention wording is flagged for owner confirmation (RESEARCH A4); executor uses the placeholder phrase from RESEARCH and leaves a visible `TODO(owner)` only in the plan, not in the rendered page.
- Includes "Dernière mise à jour : {date}" (Label).
- No prices, no marketing claims.

### 7. `/admin/avis`
- Back-office look (`pt-*` / `admin.css`), no animation. Table-like list of rows (`pt-card` rows on mobile): date, project, company, rating (number only, "4/5", no glyphs), status chip (text "Publié" / "Masqué"), actions.
- Row detail (expand or `/admin/avis/[id]`): full review text, display name, moderation history from the append-only log (action, motif, detail, author, date).
- Hide dialog: native `<dialog>` modal pattern already used in admin (or inline panel if none exists). Fields: Motif (select of 4 closed reasons, no default), Détail (textarea, required, 3 to 500 chars). Confirm button "Masquer cet avis" (`--warm` text/border, the only destructive style). Helper line states: "Le masquage n'est possible que pour illégalité. La note ou l'opinion ne sont pas un motif."
- Unhide: "Lever le masquage" requires Détail (3 to 500 chars), ghost button.
- Reissue link (per project, shown in project sheet and in this page): "Réémettre le lien d'avis", requires Détail; success state displays the new URL once in a read-only mono field with "Copier le lien" button (`aria-live="polite"` feedback "Lien copié") and warns "Cette adresse ne sera plus affichée".
- Keyboard: dialog traps focus, Escape closes, focus returns to trigger.

### 8. Footer
- Add link "Politique des avis" (FR label) to the `foot-links` block next to the legal link; style identical to sibling links. Optional second link "Avis". Do not change footer layout.

## Accessibility (WCAG AA, per PRODUCT.md)

- Contrast: `--ink` and `--ink-dim` on `--bg` / `--bg-2` meet AA; field borders use `--pt-border-strong` (3:1). Rating glyph unselected state uses `--pt-border-strong` outline (3:1) and a text echo, so state is never color-only.
- Focus visible on every control; logical tab order matches visual order; radiogroup keyboard model as above.
- Errors: `role="alert"` summary + per-field `aria-describedby`; focus moves to the summary after a failed submit.
- Live regions: character counter polite and throttled (not announced per keystroke: `aria-live` updates only at thresholds 20 and 2000), submitting status `role="status"`.
- Motion: no animation on these surfaces other than 150-200ms color/border transitions, disabled under `prefers-reduced-motion`.
- Mobile: single column below 640px, no horizontal scroll at 320px, long words in names and bodies wrap (`overflow-wrap: anywhere`).
- Language: pages are French only; `<html lang="fr">` stays as the site default for the policy and `/avis` (no th/en switch content).
