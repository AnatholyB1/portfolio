## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public submitter -> sv_submit_review (via route) | untrusted rating, title, body, names cross here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | sv_submit_review double submit | mitigate | row lock `for update` on the link + unique link_id and project_id on sv_reviews |
| T-18-02 | Repudiation | moderation | mitigate | append-only sv_review_moderation_log (deny_mutation incl. truncate), actor_id checked against sv_admins |
| T-18-03 | Tampering | review content after publication | mitigate | deny_mutation on sv_reviews update/delete/truncate, no update grant |
| T-18-04 | Information disclosure | sv_review_link_state | mitigate | single generic 'invalid' payload for missing/used/expired/invalidated; names only when valid |
| T-18-05 | Elevation of privilege | new RPCs | mitigate | revoke from public/anon/authenticated, execute only for service_role, search_path '' |
| T-18-06 | Information disclosure | token storage | mitigate | only sha256 hex hash stored (regex check), clear token never in DB or outbox payload |
| T-18-07 | Tampering | stored XSS | mitigate | body check `!~ '[<>]'`; rendering escapes (18-09, 18-10) |
