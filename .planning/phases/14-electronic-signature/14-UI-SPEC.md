# Phase 14 — UI Design Contract

> Visual and interaction contract for phase 14. Generated by gsd-ui-researcher (auto chain, non-interactive).
> Baseline: `13-UI-SPEC.md` (same design system, tokens, `pt-*` classes, copy tone). No new tokens, no new fonts, no new colors.
> Surfaces: (A) client signing page, (B) PV de recette acceptance checklist, (C) signed state in the portal Documents tab, (D) admin document card, (E) sealed PDF certificate page, (F) emails.
> Sources: 14-CONTEXT.md (D-01..D-19), 14-RESEARCH.md, 13-UI-SPEC.md.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (inherited from phase 13: custom `pt-*` CSS, no `components.json`; shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none (native elements + `pt-*` classes) |
| Icon library | `lucide-react`, 16px, `aria-hidden="true"`. New icons: `Check`, `ShieldCheck` (signed seal), `Lock` (frozen), `AlertTriangle` (reserve/refusal) |
| Font (portal/admin) | Body Manrope, headings Space Grotesk, mono JetBrains Mono (hashes, references, OTP digits) |
| Font (PDF certificate) | Manrope Latin 400 + 700 embedded (phase 13 `fontData.ts`), registered via the same helper. Certificate page is drawn with pdf-lib `drawText` using the embedded font bytes, same print palette as phase 13 Surface C |

Scoping: portal styles in `src/components/portal/project/project.css` under `.pt-root`, admin in `src/components/admin/projects/projects.css` under `.pt-admin`. New class prefix `pt-sign-*` (signing flow) and `pt-doc-*` (reused). French only, `noindex`, mobile-first (base styles target 360px, enhance at >=640px). No cinema, no custom cursor, no GSAP. No decorative animation; color/border transitions 150-200ms only (already neutralised by `prefers-reduced-motion`).

## Spacing Scale

Same scale as phase 13 (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon gap, gap between digits label and hint |
| sm | 8px | Gap between consent checkbox and its text, between row actions, OTP cell gap |
| md | 16px | Card padding, gap between consent items, checklist row padding |
| lg | 24px | Gap between steps of the signing page, card padding on desktop |
| xl | 32px | Gap between PDF viewer and consent block |
| 2xl | 48px | Page top padding below nav |
| 3xl | 64px | Not used |

Exceptions: all interactive targets min 44x44px (checkboxes get a 44px hit area via the wrapping `label`, visual box 20px; OTP cells 48px wide x 56px high on mobile, still multiples of 4; radio/check rows min-height 44px). Left rule on a reserve/refused criterion is 2px (existing `.pt-warning` filet precedent). Sticky action bar on mobile adds 16px padding plus safe-area inset.

## Typography

3 sizes (14, 16, 24), 2 weights (400, 500), identical to phase 13 web contract.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (consent text, criteria, paragraphs, form values) | 16px | 400 | 1.5 |
| Label / meta (field labels, step indicator, badges, hashes, timers, helper) | 14px | 500 (labels, badges), 400 (meta) | 1.5 |
| Heading (page title "Signer {type}", step titles) | 24px | 500 (Space Grotesk, letter-spacing -0.02em) | 1.2 |
| Display | not used | — | — |

Monospace (JetBrains Mono, family variation only): OTP digits (rendered at 24px/500 inside the OTP cells, i.e. the Heading size, not a new size), SHA-256, document reference, link hash, "Version" strings. Hashes: `word-break: break-all`, "Copier" text button.

Consent text is body 16px/400; the legal text version tag ("Texte v1") is 14px mono `--ink-dim`.

## Color

Existing dark tokens only (`globals.css`), unchanged.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` #0A0B0C | Page background |
| Secondary (30%) | `--bg-2` #111213 (step cards, tables), `--bg-3` #16181a (consent blocks, PDF frame backdrop, certificate summary, reserve fields) | Surfaces |
| Accent (10%) | `--acid` #C4F542 | see reserved list |
| Destructive / error | `--warm` #E07856 | Errors only (`.pt-error`: wrong code, expired code, blocked send, integrity broken). No destructive action in this phase (signing is irreversible but not destructive; nothing is deleted) |
| Text | `--ink`, `--ink-dim` (meta), `--ink-faint` | |
| Borders | `--line`, `--pt-border-strong` (inputs, checkboxes, OTP cells, badges) | |

Accent reserved for (exhaustive):
1. The single primary button of the current step on the signing page: "Recevoir le code" (step 2), then "Signer le document" (step 3). Only one primary is visible at a time.
2. The single primary button of the checklist page: "Continuer vers la signature" when all criteria are answered and none refused.
3. `:focus-visible` outline (2px `--acid`, offset 2px) and the checked state fill of consent checkboxes/criteria radios (`accent-color: var(--acid)`).
4. Active OTP cell focus border (`--acid`, 2px).

Not accent: "Télécharger", "Renvoyer le code", "Copier", "Exporter la piste d'audit", "Vérifier l'intégrité", "Ouvrir dans un nouvel onglet" (all `.pt-btn-ghost` or `.pt-btn-text`). The "Signé" badge is neutral like phase 13 badges: meaning is carried by text plus `Check`/`ShieldCheck` icon, never by green. The integrity result OK/rompue is carried by text and icon (`Check` vs `AlertTriangle`), with `.pt-error` color only for "rompue".

## Surface A — Client signing page

Route: `/espace-client/documents/[documentId]/signer`. Server component shell + one client component `SigningFlow` (state machine). Accessible only to the signing client of the project (RLS). Document types: Devis, Contrat, PV de recette (PV goes through Surface B first). No prices are added by this phase beyond what the issued PDF already contains (the PDF shows amounts, the page chrome around it does not).

### A1. Layout (mobile-first, single column, max-width same as project page)

Top: `Link` "Retour aux documents" (`.pt-btn-text`, `ChevronLeft` 16px) to `/espace-client/documents`. Then `h1.pt-heading`: "Signer le devis" / "Signer le contrat" / "Signer le procès-verbal de recette". Under it, meta line (14px `--ink-dim`): "Version {n} · émis le {date}".

Step indicator `ol.pt-sign-steps` (14px, text only, `aria-label="Étapes de la signature"`): "1. Lire", "2. Consentir", "3. Confirmer par code". Current step has `aria-current="step"` and weight 500; completed steps show `Check` icon. Not a progress bar.

Steps are sequential sections of the same page (no route change):

**Step 1 — Lire le document.** `.pt-card`. `<iframe title="Document à signer : {type}">` from a short-lived signed link (original issued bytes, same bytes as the hashed document). Height 480px (<640px), 720px (>=640px), width 100%, border 1px `--pt-border-strong`, backdrop `--bg-3`. Always visible fallbacks under it: `.pt-btn-text` "Ouvrir le document dans un nouvel onglet" (`ExternalLink`) and `.pt-btn-text` "Télécharger le document" (`Download`). Mobile note (14px `--ink-dim`, shown always): "Sur téléphone, l'affichage intégré peut être limité. Utilisez « Ouvrir le document » pour le lire en entier." Short line below: "Référence {reference} · Empreinte {first 12 hex}" (14px mono `--ink-dim`). No forced read-to-bottom (D-02). Opening the viewer logs an audit link (no UI feedback).
If the iframe signed link fails: `.pt-error` in `aria-live="polite"`: "Le document n'a pas pu s'afficher. Ouvrez-le dans un nouvel onglet ou réessayez dans un instant." plus `.pt-btn-ghost` "Réessayer".

**Step 2 — Consentir.** `.pt-card` containing `fieldset` with `legend` (16px/500) "Avant de signer". Two unchecked checkboxes, each in a `label.pt-sign-consent` (`--bg-3`, 1px `--pt-border-strong`, 8px radius, 16px padding, min-height 44px, checkbox left, text right, gap 8px). The exact legal text of each is displayed in full, never truncated or behind a link, followed by "Texte v{n}" (14px mono `--ink-dim`). Texts are sourced from a versioned constant (legal review pending, see Open Items):
1. Consent to electronic signature. Placeholder text v1: "J'accepte de signer ce document par voie électronique, au moyen d'un code à usage unique envoyé à mon adresse e-mail. Je reconnais que cette signature vaut mon accord au contenu du document."
2. Evidence agreement. Placeholder text v1: "J'accepte que les éléments techniques collectés lors de la signature (date et heure, adresse IP, empreinte du document, journal des actions) soient conservés et puissent être produits comme preuve de ma signature."
Primary button "Recevoir le code" `.pt-btn-primary`, `disabled` until both are checked; `aria-describedby` points to helper "Cochez les deux cases pour recevoir le code." Click: button label "Envoi du code…" and `disabled`; consents are logged server-side with the exact text and version. Signer identity block above the checkboxes (14px, `--ink-dim`): "Signataire : {nom}, {fonction}" and "Le code sera envoyé à {email masqué, ex. a***@exemple.fr}".

**Signer mismatch (D-04).** If the onboarding signer does not match the logged-in user, steps 2-3 are replaced by `.pt-card` with `h2` "Vous n'êtes pas le signataire désigné" and `.pt-helper` "Ce document doit être signé par {nom du signataire}. Connectez-vous avec l'adresse e-mail du signataire, ou écrivez-nous pour modifier le signataire." The document stays readable (step 1 remains) and downloadable. Buttons: `.pt-btn-ghost` "Se déconnecter" and `.pt-btn-text` "Écrire à Sèvalys" (mailto).

**Step 3 — Confirmer par code.** Appears after the code is sent, step 2 collapses to a read-only recap line with `Check`: "Consentements enregistrés". Contents:
- Status line (`aria-live="polite"`, 16px): "Code envoyé à {email masqué}. Il est valable 10 minutes."
- OTP input: one visually segmented field of 6 digits. Implementation contract: a single `<input type="text" inputmode="numeric" autocomplete="one-time-code" maxlength="6" pattern="[0-9]*">` (paste and SMS/e-mail autofill work) styled as 6 cells via background/letter-spacing, or 6 linked inputs with paste splitting; label `.pt-label` "Code à 6 chiffres" (visible). Digits JetBrains Mono 24px/500, cell 48x56px, gap 8px, border `--pt-border-strong`, focused cell `--acid` 2px. Error state border `--warm` plus `.pt-error` text under it, linked via `aria-describedby`, `aria-invalid="true"`. Auto-submit is not used; submission only via the button or Enter.
- Primary `.pt-btn-primary` "Signer le document", `disabled` until 6 digits. In flight: "Signature en cours…", `disabled` (double-click safe: server idempotent).
- Secondary row: `.pt-btn-text` "Renvoyer le code". After each send it is `disabled` for 60 s with visible countdown label "Renvoyer le code (45 s)" updated every second but announced only at start and at 0 (no per-second live announcements). After the 5th send within an hour it is disabled with helper "Limite atteinte : 5 envois par heure. Réessayez plus tard ou écrivez-nous." Also `.pt-btn-text` "Modifier mes consentements" is NOT offered (consents are final once logged).
- Mobile: the primary button sits in a sticky bottom bar (`--bg-2`, 1px top `--line`, 16px padding + `env(safe-area-inset-bottom)`) only on step 3 so it stays above the on-screen keyboard; desktop: inline.

### A2. States (all `aria-live="polite"`, error text `.pt-error`)

| State | Copy |
|-------|------|
| Code wrong, attempts left | "Ce code n'est pas correct. Il vous reste {n} essai(s)." (field cleared, focus back to field) |
| 5 attempts used | "Trop d'essais. Ce code n'est plus valable. Demandez-en un nouveau." (field and sign button disabled, "Recevoir un nouveau code" `.pt-btn-ghost` appears, respecting the 60 s delay) |
| Code expired | "Ce code a expiré. Demandez-en un nouveau." (same treatment) |
| Resend too soon | "Patientez {n} s avant de demander un nouveau code." |
| Hourly cap | "Limite atteinte : 5 envois par heure. Réessayez plus tard ou écrivez-nous." |
| Code sent (success) | "Code envoyé à {email masqué}. Il est valable 10 minutes." (not `.pt-success` green, plain status) |
| Send failure | "Le code n'a pas pu être envoyé. Réessayez dans un instant ; si le problème continue, écrivez-nous." |
| Seal/sign failure | "La signature n'a pas pu être finalisée. Aucune signature n'a été enregistrée. Réessayez ; si l'erreur persiste, écrivez-nous." (document not signed, code still valid if not consumed; otherwise ask for a new code) |
| Already signed (reopen link) | The page renders the Signed state below instead of the flow. |
| Document replaced (a newer version exists) | `.pt-warning` card: "Cette version a été remplacée par la version {n}." with `.pt-btn-ghost` "Voir la version {n}". Flow disabled. |
| Document not signable at this step | "Ce document n'est pas encore à signer." with link back |

### A3. Success state (replaces the flow, focus moves to its `h2` with `tabIndex=-1`)

`.pt-card` (`--bg-2`): `ShieldCheck` 16px + `h2.pt-heading` "Document signé". Body: "Merci. Votre signature a été enregistrée le {date} à {heure} (heure de Paris)." Meta list (14px): "Référence {reference}", "Empreinte du document scellé {first 12 hex}". Buttons: `.pt-btn-ghost` "Télécharger le document signé" (signed link of a few minutes, opens download, label "Préparation…" while generating, hash verified server-side, error copy: "Le téléchargement n'a pas pu démarrer. Réessayez dans un instant ; si le problème continue, écrivez-nous.") and `.pt-btn-text` "Retour aux documents". Line: "Un e-mail de confirmation vous a été envoyé." No accent button.

## Surface B — PV de recette acceptance checklist

Route: `/espace-client/documents/[documentId]/signer` for a PV renders the checklist as step "0" before the standard flow (the step indicator reads "1. Vérifier les critères", "2. Lire", "3. Consentir", "4. Confirmer par code"). Criteria are the exact acceptance criteria of the issued cahier des charges, numbered, as repeated in the PV.

**Layout.** `h1` "Recette du projet", intro (16px): "Pour chaque critère, indiquez s'il est livré. Vous pouvez signaler une réserve ou refuser un critère." Then `ol.pt-sign-criteria`, one `li` card per criterion (`--bg-2`, 1px `--line`, 8px radius, 16px padding, 16px gap between cards):
- Criterion text (16px/400) preceded by number "{n}." (14px mono `--ink-dim`).
- Radio group (`fieldset`, `legend.pt-sr-only` "Critère {n} : {texte}"), three radios stacked on mobile (each a 44px-high `label`), inline row >=640px: "Livré", "Livré avec réserve", "Non livré (refus)". Unselected by default (no precheck).
- "Livré avec réserve": reveals a `textarea` (label "Décrivez la réserve", required, min 3 rows, max 1000 chars, counter "{n} / 1000" 14px `--ink-dim`). Card gets 2px left rule `--pt-border-strong` and `AlertTriangle` 16px next to the radio label.
- "Non livré (refus)": reveals a `textarea` (label "Pourquoi ce critère n'est-il pas livré ?", required, max 1000), 2px left rule `--warm`, helper under it (14px): "Un critère refusé empêche la signature. Sèvalys est prévenu et vous enverra un procès-verbal corrigé."

**Summary bar** below the list (`.pt-card`, `--bg-3`, `aria-live="polite"`): "{x} sur {total} critères validés · {y} réserve(s) · {z} refus". Layout is sticky bottom on mobile, with the action button.

**Actions.**
- All answered, zero refusals: `.pt-btn-primary` "Continuer vers la signature" (enabled). If reserves exist, a `.pt-warning` note above it: "Vos réserves seront inscrites au procès-verbal signé. La signature reste possible."
- Any unanswered: button `disabled`, `aria-describedby` helper "Répondez à chacun des {n} critères restants." (count updates).
- Any refusal: primary replaced by `.pt-btn-primary` "Envoyer mon retour à Sèvalys" (sends the refusals; the OTP step is not reachable). On success: `.pt-success` card "Retour envoyé. Sèvalys a été prévenu et vous enverra un procès-verbal corrigé. Aucune signature n'a été enregistrée." with `.pt-btn-text` "Retour aux documents". Error: "Votre retour n'a pas pu être envoyé. Réessayez ; si l'erreur persiste, écrivez-nous."
- `.pt-btn-text` "Enregistrer et revenir plus tard" is not offered: answers are held in the page and logged on advance (checks/reserves are written to the audit chain when the client clicks the continue/send button, not per click). A warning-free `beforeunload` is not used.

After "Continuer", the answers are shown read-only in a recap above step "2. Lire" ("Vos réponses : {x} validés, {y} réserve(s)") with `.pt-btn-text` "Modifier mes réponses" available until the consent step is validated.

State when the PV is already answered/signed: Signed state (A3) with reserves recap list if any.

## Surface E — Sealed PDF certificate page (last page appended)

Print contract, same palette and type system as phase 13 Surface C: A4, margins 48/48/64/48, white paper, Ink #111111, Muted #5A5A5A, Rule #D4D4D4, Band #F4F4F2, Manrope 400/700, sizes 8 / 10 / 12 / 24 pt, line heights 1.5 / 1.2, no accent color, no images, all text extractable.

Layout, single page (the content is bounded so it never overflows; long criteria lists for the PV are on the original pages, the certificate lists reserves in a compact block that may extend to a second certificate page, repeating the footer):
1. Title (24 pt bold): "Certificat de signature électronique". Under it (8 pt Muted): "Signature électronique simple par code à usage unique".
2. Band block "Document" (Band fill, 16 pt padding): Type, Référence, Version du document, Version du modèle, Émis le.
3. "Empreinte de l'original (SHA-256)" (8 pt Muted label) then the 64-hex string in two 32-char lines (10 pt, monospace substitute: Manrope with tabular spacing is acceptable, no mono font embedded).
4. Block "Signataire": Nom, Fonction, Adresse e-mail.
5. Block "Signature": Date et heure (Europe/Paris), Date et heure (UTC), Adresse IP, Méthode "Code à usage unique envoyé par e-mail".
6. Block "Piste d'audit": Nombre de maillons, "Empreinte du dernier maillon (SHA-256)" in two lines.
7. PV only: "Critères d'acceptation validés" (table N° / Statut "Livré" or "Livré avec réserve" / Réserve text) when reserves exist; otherwise "Tous les critères ont été validés sans réserve."
8. Mentions (8 pt Muted, one paragraph): signature simple (not advanced/qualified), the evidence agreement accepted by the signer with its text version "Texte v{n}", and "Sèvalys ne contre-signe pas ce document : son émission vaut engagement du vendeur." (legal wording pending review).
9. Footer (fixed, 8 pt Muted): "Sèvalys · {reference}" left, "Certificat · page {n} / {total}" right. No "Modèle" suffix.

Rules: all dates and values come from the audit trail rows only (no `new Date()` at render), formatted with the same `formatDateFr`/UTC helpers, `U+00A0` spacing rules from phase 13. Characters must exist in the embedded subset (no U+202F). Original pages are copied untouched, the page numbering of the original is not rewritten.

## Accessibility and Interaction Notes

- Signing flow is a `form` per step; Enter submits the active step only. Focus management: after "Recevoir le code" succeeds focus moves to the OTP field; after wrong code focus returns to the field and the error is announced; after signature focus moves to the "Document signé" heading (`tabIndex=-1`); after a checklist refusal send, focus moves to the confirmation card.
- Status/error regions are `aria-live="polite"`; the resend countdown is announced only at start and when it reaches 0. Do not use `role="alert"` for the attempts counter.
- OTP: `autocomplete="one-time-code"`, `inputmode="numeric"`, paste of 6 digits fills the field, non-digits stripped, no `type="number"`.
- Checkboxes and radios are native inputs inside `label`s (whole row clickable, 44px). Required reserve/refusal textareas are linked with `aria-describedby` and `aria-invalid`.
- Color is never the only signal: reserve/refusal use icon + text, signed uses icon + text, integrity broken uses icon + text.
- Contrast: reuse phase 10 verified tokens (`--ink-dim` only for 14px meta). The disabled primary button keeps a 3:1 border for visibility.
- iframe has a `title`; a non-iframe fallback (open in new tab, download) is always rendered, not conditional on detection. Mobile PDF iframes are unreliable (RESEARCH Pitfall 6).
- Mobile-first: base 360px; sticky action bar on steps with a primary button; no horizontal scroll; tables fall back to the phase 13 stacked-card mode.
- No timeout on the page except the code validity (10 min), which is stated in text; when expired the UI offers a new code without reloading.
